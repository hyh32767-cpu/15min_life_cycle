# 社区解读与智能路线安排

2026-10-16，用户要求直接落地简洁版本，随后追加“选好沿途后说要办什么、多久之后，大模型推荐并同步前端，仍能自己改”。本轮完成两个入口，没有新增聊天页面或替换现有组件流程。

## 使用方式

- **社区解读**：设施社区评分下点“看看建议”，生成一段短解读。只有所选服务全部查询完成时可用，固定说明仅针对本次检索设施和采样点。更换类别/统计或中心后旧解读清除；失败可手动重试，不改变原评分、地图和报告结果。
- **帮我安排**：选好起终点后，在沿途面板输入“先买药再取快递，药店停留三分钟，三十分钟内到终点”。模型只解析类别、先后关系和时间；真实候选和路线由原POI/矩阵/规划器提供。成功后所选门店按顺序进入原途经点列表，地图复用原方案路线层，支持原有调整顺序、增删、换地点和修改停留。

已有途经点保留，同类智能任务复用，不因重复点击一直追加。一次自然语言最多3类任务，含已有地点最多5处；新类别最多取沿途召回的2个候选参与真实计算，不宣称全域最优。未说明停留时长时使用现有停留设置，并在输入框下明示。

“多少分钟内办完/到终点”按出发时间计算总时限；“最多多花/绕路多久”按基准路线加额外时间，额外时间包含停留。该简版不单独支持“只限制额外步行、但不限停留”的自然语言约束。现有最晚到达仍是硬约束，取更紧截止；实际营业时间可解析时带入原规划器，未知不伪造全天营业。

方案应用后时间限制保存在计划状态中，手动排序、修改地点再规划仍生效；更改端点/出发/最晚到达或复位时清除。尚未扩展历史收藏的持久化字段，不承诺保存后跨刷新保留AI时限。新安排不可行/接口失败时回到原计划；用户中途编辑自己的途经点或更换路线后，迟到响应不能覆盖。

## 接口与模型

- POST /api/community/insight，仅传29类服务的ID、覆盖采样数、总采样数和候选数；服务名称由后端白名单提供，不发送坐标、地址或门店详情。分数由程序复算，模型只输出短文，不接管分数和候选动作。
- POST /api/route/intent，仅传240字内的需求文本。返回封闭类别、整数时长和顺序标识；Pydantic拒绝未知类别、重复类别及冲突时间。模型没有地图工具，不返回门店或路线几何。
- OpenCode Go/deepseek-v4.1-flash，显式关闭推理；社区最多350输出token，路线500，15秒超时且不自动重试。单进程串行，一分钟最多6次未命中请求，最多64条/10分钟缓存。同内容不重复消费模型；查询与算路缓存继续沿用原实现。
- 本地开发复用本机OpenCode Go登录。生产凭据单独放在root权限600的/etc/shunlu-llm.env，通过systemd读取，不在发布包、Git、浏览器或日志中。远端API并非本地推理模型；没有禁用TLS验证。
