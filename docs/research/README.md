# 算法研究导航

本项目研究的是：在只能查询步行用时、查询次数有限的条件下，怎样近似重建可达范围，并把它用于社区服务观察和沿途办事。

当前产品使用 `grid-frontier-barrier-v4`。早期射线、扇形、完整网格和插值实验是研究基础，各阶段有不同范围、预算和参考数据，不能拼成一张统一的性能排行榜。

## 当前方法

### 测量与区域推断

百度步行矩阵回答有方向的 `T(中心, 测点)`。100米网格覆盖圆形区域，15分钟主圈半径上限1100米，共377个位置（含逻辑中心），最多376个外部位置。中心锚点不作为一次外部OD查询，也不据此伪造一条API测时记录。

主阶段按到中心的欧氏距离带由外向内推进，同一层全部完成后再进入内层。每批最多50个位置；外侧超时或明确断路的点推动前沿继续向内，找到可达点后停止该分支深入。这节省了部分内部查询，同时引入内部可能有遗漏的假设。

因此主阶段之后还有独立的内部检查：两条贯穿轴线逐格检查，辅以离轴抽检；从已经观察到的超时、断路点向未知邻格追踪，保留可达桥梁和通路。内部追踪可以向外接续，不能把它称作严格外向内主阶段。

必要测量未知或预算用尽时保留部分状态。圆边界存在可达点时标记触边，范围之外不是已知不可达。策略完成也仍可能包含未测内部的区域估计。

### 加载绘图与分析几何

| 数据 | 生成方式 | 用途 |
| --- | --- | --- |
| 实测样本 | 步行API或有效同方向缓存 | 测量证据，未知不补零 |
| 加载预览线 | 从参考圆出发，按已得测点逐批更新 | 只用于等待过程的连续反馈 |
| 完成描线 | 实测样本的Delaunay线性时间场 | 地图展示；局部圆角只作视觉处理 |
| 分析多边形 | 网格前沿与内部屏障推断，保留孔洞及多分量 | 设施过滤、覆盖采样和面积 |

相关实现：[时间场描线](../../core/time_contour.py)、[任务发布](../../api/app/services/grid_frontier_service.py)、[地图图层](../../web/src/components/map/useGlobalMapLayers.ts)。地图线条更顺滑不意味着测量精度提高。5/10/15分钟分别求解、复用OD，不能按比例缩小主圈。

### 社区与路径

设施评分使用圈内有限采样点到参评设施的有向步行用时。一家设施可以覆盖多个位置，覆盖率不是门店数量占比。已被任一家设施证明可达的点不必再测其他设施；尚未覆盖的点需要足够证据，接口错误不能当作不可达。

沿途范围通过多个完整中心的分析几何并集形成，固定15分钟；缺测中心不以预览填面替代。真正的绕行是 `T(S,P)+T(P,H)-T(S,H)`，多站计划还要整体考虑顺序、停留、开放时间和最后到终点，不能把每家独立绕行值相加。

对应代码：[沿途服务](../../api/app/services/route_band_service.py)、[绕行](../../core/detour.py)、[规划](../../core/planner.py)、[时间窗](../../core/timewindow.py)。

## 哪些比较可以得出什么

### 新点真实冷启动

| 地点 | 原自适应扇形 | 网格 | 扇形/网格查询位置 | 扇形/网格矩阵HTTP |
| --- | ---: | ---: | ---: | ---: |
| 重庆湖广会馆，v3 / 1公里 | 124.738秒 | 47.624秒 | 286 / 265 | 20 / 10 |
| 杭州武林广场，v4 / 1.1公里 | 195.083秒 | 146.547秒 | 337 / 294 | 20 / 13 |
| 苏州月光码头，v4 / 1.1公里 | 148.497秒 | 101.131秒 | 337 / 230 | 19 / 9 |

这些是15分钟主圈，不包含5/10分钟、设施统计和整页加载。每次使用独立空缓存，但不是重复多轮统计。原扇形括界上限1.8公里；重庆与后两地的发送窗口不同，上游延迟也随时段变化。不能把时间差全部归因于算法，不能据此声称同范围同精度下普遍加速。首次可发布快照也不等于浏览器已显示。

失败和中断另存，不纳入成功用时；后两地完成的四轮共1198对、61次矩阵HTTP，失败另156对、6次HTTP。详见[原报告及来源](../78-两个新点一公里一网格计时.md)。

### 兰州内部河道

在同一707个历史检查位置上，屏障修复前后误可达100→46、漏可达76→92，点级IoU 0.6589→0.7013。这个诊断显示减少误填的代价与收益，而非“河流问题已完全解决”。历史检查点与新增测量不是同时采集，不能把混合缓存的复查耗时写成冷启动性能。

### 离线网格与扇形参照

早期两组五城实验共同窗口只有1×1公里，即使格点参考场面积IoU为1，也不能说明真实边界完全准确。非格点检查仍有错误。后来2×2公里、100米格的34中心盘点只有王府井具备完整441位置，不是34城均有同等参考数据。详见[72](../72-两公里范围百米网格全量盘点与重算.md)。

早期研究指标有的来自“射线＋时间场＋复通带”融合，有的只比较保存的射线多边形；评价前应核对组成、日期、范围和测点是否独立。可视平滑、历史IoU和在线分数不能互相替代。

## 查询成本与缓存

统计时区分：算法请求的位置数、有效缓存命中数、新发OD对数、HTTP批次数、重试和真实等待。矩阵成本按 `origins × destinations`，不是只按一次HTTP计费或限流。单批50对与50 QPS是两回事。

网格任务共用串行节奏，再叠加正式网关的窗口、分接口限流和退避。短测未触发限流不能证明持续安全。限流延后请求，配额耗尽停止新增，错误不改成零秒。相关窗口研究见[62](../62-矩阵HTTP在途并发受控探测.md)至[67](../67-新AK与串行策略视频主圈重测.md)，实现见[core/ratelimit.py](../../core/ratelimit.py)。

原始响应缓存保留方向、坐标和有效期，派生结果另含算法版本和参数；更新绘图不得修改历史测值。缓存命中不续写原始有效期，也不能把回放当成本次实时请求。
