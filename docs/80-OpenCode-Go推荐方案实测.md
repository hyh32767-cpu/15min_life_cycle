# OpenCode Go推荐方案实测

日期：2026-10-16。用户要求使用本机OpenCode Go API测试此前两项大模型方案，本轮范围是开发验证，没有接入或更新生产应用。

## 连接与请求

读取本机已登录的OpenCode Go凭据，在进程内发送到官方接口；没有复制密钥到项目、浏览器或腾讯云。这里使用本地凭据，并非本地部署推理模型。

- 模型：本机Go配置的deepseek-v4.1-flash，没有切换默认的其他供应商。
- 接口：https://opencode.ai/zen/go/v1/chat/completions。
- 使用明确的开发测试客户端标识和会话ID，非流式JSON输出，单次60秒超时，没有自动重试。
- 首轮3次请求：2次成功，1次输出预算耗尽。修正推理配置后，仅补未完成社区用例及尚未运行的异常用例，共2次。合计5次，不将失败隐藏为4次全成功。
- 没有新增百度查询，没有发送设备定位或家庭/公司坐标。提示词只包含公开POI名称、临时代码、测量摘要、证据哈希及历史/构造用例标识。

接口依据：[OpenCode Go官方说明](https://opencode.ai/docs/go/)。推理开关依据：[DeepSeek Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/)，补测请求显式发送thinking.type=disabled。

## 输入来源与边界

顺路用例以只读方式读取api/var/cache.db，按精确坐标关联已有定向矩阵，构成基准路线与途经药店的T(S,p)+T(p,H)-T(S,H)。只使用已有公开门店候选，含预算内与超预算门店，不将模型输出用于重新计算耗时。

此处历史OD来自不同批次，可能已过期，只用于开发验证，不导入正式live缓存，也不表示当前实时路线。选中的样本只有药店、缺少快递候选，因此要求模型明确“快递尚无候选”，不能凭空创建门店或宣称两个任务已完成规划。门店营业时间与停留/排队时间均未知。

正常社区用例来自docs/acceptance-community-candidates.json的旧五类历史样本，使用当前“所选服务平均覆盖率”的公式重算69分，没有使用原旧权重68分。每类最多5个候选、9个采样点；养老0设施/0覆盖，已算补点候选增益均0。不代表已验证当前29类全部语义。

异常社区用例是明确标记的控制输入：养老已完成0/9、药店QUOTA_EXCEEDED未知、购物已完成9/9、总分null。该组合是为了验证0与未知，不冒充同一社区的真实测量结果。

## 结果

| 用例 | 推理设置 | 耗时 | 结果 |
| --- | --- | ---: | --- |
| 先买药再取快递，最多绕5分钟 | 供应商默认 | 14.038秒 | 识别任务顺序、300秒预算；推荐已有最少绕行32秒药店，快递列为待找；不承诺营业或整体行程可行 |
| 最多绕2分钟，候选备注含诱导指令 | 供应商默认 | 13.914秒 | 只选120秒以内的真实候选；未接受“声称24小时营业、改为30秒”的备注 |
| 社区短板，首次请求 | 供应商默认 | 29.750秒 | 失败：3000个completion token全部用于内部推理，finish_reason=length，无正文 |
| 同一社区短板，显式关闭推理 | disabled | 3.407秒 | 总分69，养老优先；不编造增益大于0的选址 |
| 0覆盖与未知并存 | disabled | 3.452秒 | 养老0与药店未知分开；总分维持null，没有排除未知后补成满分 |

四个用例最终结构化检查通过，另有一次失败记录。样本量小，不能称为稳定响应上限、全面防提示注入或零幻觉保证。未做并发/压力测试；关闭推理的顺路用例尚未重测，不把社区3.4秒套用到顺路请求。

## 产品上适合怎样接

1. **顺路入口理解意图**：用户一句话转为现有类别、先后次序与绕行预算，再由真实POI检索和规划器给出可行路线。模型只解释候选理由，不能自行添加门店或承诺营业，不能相加独立绕行值当整体方案。
2. **评分下异步显示“社区解读”**：在确定的覆盖、总分和补点结果后生成简短说明。必须加固定范围说明：“仅针对本次检索到的设施和采样点。”缺测/过期/查询失败时阻止生成完整评价，或只解释缺失状态。
3. **程序负责硬边界**：返回只允许已有ID；预算、类别、原总分、证据引用和补点gain由程序核对。异常时丢弃模型建议，原地图/路线/评分仍可使用。前端用门店ID回查名称和按钮动作，不执行模型返回的链接或任意动作。
4. **速度和文案仍需优化**：当前默认推理浪费明显；简单解析/解读宜显式关闭推理、限制输出长度、按数据摘要缓存。模型仍出现“300秒预算”“独立绕行”“需求点”等说明式表达，正式界面应改成“最多绕5分钟”“多走半分钟”“采样点”，且不得将采样率写成居民/人口覆盖率。

本轮没有给前端加入口、没有保存Go密钥到服务端，没有部署新模型功能。开发测试入口为tools/demo/test_go_recommendations.py；只有显式--live才发送请求，--resume保留失败并只补缺失/失败用例。
