# 五十对连续发送间隔边界实测

2026-10-16用户要求继续测清边界，而非停在单次成功或任一通过档位。本轮测试单批固定50对的持续发送间隔，不重复测试超过官方单批上限的参数，也不把HTTP在途并发数当作路线吞吐。

## 方法

- 在腾讯云同一服务端AK上直连百度步行矩阵接口；每请求1起点×50终点，公开王府井中心，排除有效缓存中的OD。
- 先将18秒间隔延长至连续6批，再在既有失败档与通过档之间二分，约1秒分辨率。
- 搜索档连续6批；出现401立即结束该档，65秒冷却后再测试下一个档位，没有隐式重试。
- 最终候选档再连续12批验证；若失败，推进失败下界并继续放慢、搜索和验证，不把6批短测直接当作最终结果。
- 按相邻请求发出时刻安排间隔，不按响应结束时刻额外累加；相邻成功档之间也保持新档间隔。成功档之间未清空账号侧累计用量。
- 每次尝试写入产品账本`matrix-envelope-20261016`阶段，成功原始响应写入正常产品缓存；不写研究账本，不输出密钥，不改变线上限流、环境配置或算法。
- 独立探测进程绕开应用内排队和自动冷却，但保留自身固定发送节奏、失败停止与冷却、最多80请求/4000对的硬预算。预算是上限，并非预定全部消耗。

工具：`tools/demo/benchmark_matrix_envelope.py`，必须显式使用`--run-live`才会发送请求。证据文件在每次请求后保存，避免中途中断丢失结果。

## 解释边界

这是指定账号、接口、单批大小和测试时段的有限次实验，不是百度正式权益或无限期容量保证。以一秒分辨率报告本轮“失败档／连续12批通过档”；若非限流错误或预算耗尽，会保留停止状态，不把未测量档位推断成成功。其他共享账号流量无法完全排除。
