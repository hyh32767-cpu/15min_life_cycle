# 「顺手」全产品 PRD：通勤规划、独立等时圈与社区体检

> 版本：v1.0（比赛版整合稿，2026-09-22）  
> 目的：给产品、前端布局生成器和后端实现共同使用。本文覆盖整个应用，不把等时圈限定为通勤页里的一个面板。

## 1. 产品定义

### 1.1 一句话

「顺手」帮助用户回答三件事：**下班路上能不能顺手办完事、某个地点步行能到哪里、一个社区的生活服务是否够用**。

### 1.2 三条主线

1. **个人通勤规划**：公司 → 家的路线、沿途 POI、停留时间、回家截止时间和多任务重排。
2. **独立等时圈探索**：地图选点或自定位，按步行时间生成真实道路等时圈，查看圈内服务和可达性报告。
3. **社区生活体检**：以社区中心和居民采样点为中心，评估医疗、教育、购物、药店、养老供给，定位盲区并给出处方。

### 1.3 产品边界

- 百度能提供的地址、坐标、POI、路线、距离、导航耗时和营业时间优先使用真实 API 或 API 缓存。
- 排队、店内办理、购物停留、用户偏好、临时关店和事件延误属于模拟字段，必须显示“模拟假设”。
- 不把 POI 搜索结果说成现实全量；不把直线距离说成步行可达；不把模拟事件说成实时路况。
- 比赛版不要求登录、支付、真实 GPS 持续追踪或后台推送。

## 2. 用户与核心任务

| 用户 | 任务 | 成功结果 |
| --- | --- | --- |
| 下班办事的人 | 找一家顺路药店/超市并按时回家 | 看到真实绕行、模拟停留、预计到家时间和余量 |
| 周边探索者 | 从当前位置看 5/10/15 分钟能走到哪里 | 获得地图等时圈、圈内 POI、可解释报告 |
| 社区运营者/评委 | 判断社区服务缺口和障碍 | 获得分类覆盖率、盲区类型、障碍证据和新增点处方 |
| 演示人员 | 在联网环境完整展示链路 | 真实百度 API 调用可追踪，缓存只用于减少重复调用 |

## 3. 信息架构与导航

桌面端使用顶部导航，移动端使用底部导航或菜单。页面路由如下：

| 路由 | 页面 | 主要内容 |
| --- | --- | --- |
| `/` | 通勤沿途 | 公司/家、基准路线、沿途 POI、绕行和选中 POI 等时圈 |
| `/isochrone` | 等时圈 | 地图选点/自定位、步行阈值、等时圈、圈内 POI 和报告 |
| `/plan` | 今天安排 | 任务编辑、候选 POI、服务时长、截止时间和规划目标 |
| `/plans/:id` | 方案详情 | 方案对比、路线时间线、来源和假设 |
| `/plans/:id/run` | 执行与重排 | 虚拟时钟、完成/跳过、关店/延误事件、重排差异 |
| `/explore` | 时间空档 | 预算时间内可去并能返回的活动/POI |
| `/community` | 社区体检 | 五类设施、盲区、障碍诊断、选址处方和报告 |
| `/cases` | 历史案例 | 多城市实验案例、指标、地图、数据来源和局限 |

全局右上角显示“真实 API / 缓存命中”、API 配置状态和本次数据来源；全局提供“复位”和“生成报告”。

## 4. P0 功能规格

### 4.1 全局入口、地点与数据模式

#### 入口

- 每个地图页都提供地址搜索、地图点选、当前位置三个入口。
- 搜索结果必须先让用户确认候选名称和位置，再开始路线或等时圈计算。
- 浏览器定位需要显式权限；拒绝权限时保留地图点选和地址搜索，不阻塞应用。

#### 地图点选状态

`idle → selecting → candidate-confirm → ready → loading → partial/complete/failed`。

地图点击先放置临时十字标记，显示坐标和“以此处规划”按钮；确认后才调用 API。拖动标记不会自动发起昂贵计算。

#### 统一来源标签

`live-api`、`api-cache`、`synthetic-assumption`、`user-input`、`derived`、`unknown`。所有卡片、报告和导出数据均可展开查看来源。

### 4.2 通勤沿途：公司到家顺路办事

#### 输入

- 公司地址、家地址、出发时间、回家截止时间。
- POI 类别：超市、药店、咖啡、快递、餐饮、自定义关键词。
- 最大额外步行/绕行时间、服务停留时间、是否允许整体换路。

#### 主流程

1. 地址确认 → 百度步行路线获得基准路线、距离和耗时。
2. 沿路线分段搜索 POI，分页、去重、记录召回窗口和来源。
3. 对候选计算公司→POI→家及必要的有向路线矩阵。
4. 卡片展示额外路程、模拟服务、预计到家、余量、营业时间和可行性原因。
5. 选中 POI 后按需生成该点 5/10/15 分钟等时圈，并显示最佳接入/返回证据。
6. “加入今天安排”把 POI 带入规划页；用户可以改服务时长或换同类候选。

#### 候选卡必备字段

名称、类别、营业时间（未知时明确显示未知）、距离/耗时、额外耗时、服务时长、预计到家、剩余余量、来源徽标、不可行原因。

#### 关键口径

路线可达性使用真实步行耗时；服务和排队只能是用户输入或固定 seed 模拟。去程与返程不假设对称。POI 与等时圈相交不是最终可行性，最终以路线矩阵和时间预算为准。

### 4.3 独立等时圈

这是独立页面和独立导航入口，也可从通勤候选进入。

#### 输入

- 地图点击、地址搜索或浏览器当前位置作为起点。
- 步行时间阈值预设：5、10、15、20 分钟；支持 3–30 分钟范围内的自定义值。
- 可选出发方向、城市/区域、POI 类别筛选。

#### 计算与展示

1. 使用百度步行矩阵按 8 向起步、二分探测和证据驱动加密生成边界。
2. 输出主多边形、测量射线、探针点、失败射线和预算跳过射线；不以固定圆或直线距离冒充结果。
3. 支持叠加多个阈值，最多比较 3 个起点或 4 个时间层，颜色和图例必须稳定。
4. 圈内 POI 使用区域检索召回，再用起点→POI有向路线矩阵过滤真正可达项。
5. 点击 POI 可查看名称、类别、营业时间、步行距离/时间、来源，并加入通勤计划或今天安排。

#### 等时圈报告

- 起点、坐标系、阈值、生成时间、算法版本和数据模式。
- 最大/最小/中位边界距离；有效、失败、跳过射线数；实际 API 对数和缓存命中。
- 近似面积、周长和边界说明：这是由实测射线重建的近似值，不声称完整路网可达面积。
- 圈内 POI 按类别统计、可达比例、营业时间未知数量。
- 警告：河流/桥梁、路网缺口、配额截断、POI 召回上限、方向不对称。
- 导出 Markdown/JSON/CSV/打印版报告，生成可复制链接（比赛版可为本地状态链接）。

#### 等时圈页面布局

桌面：左侧“起点与阈值”控制栏，中间 60% 宽地图，右侧“结果/报告/圈内 POI”抽屉。移动端：地图占上半屏，控制和报告使用可拖拽底部抽屉。

### 4.4 今天安排与整体规划

#### 任务模型

任务可以是固定 POI、类别任选或自定义地点；字段包括名称、地点候选、服务时长、是否必做、营业窗口、截止时间和前置任务。

#### 规划目标

- 最快回家
- 最少额外步行
- 保留公司→家基准路线
- 允许整体换路

规划器先用真实/缓存 OD 构建有向矩阵，再枚举任务顺序和候选，剪枝营业窗口、前置关系和 deadline。无解时必须说明是无路、时间不足、营业冲突还是数据缺失。

#### 方案卡

展示总耗时、步行距离、等待、服务、回家时间、余量、任务顺序、每段来源和选择理由。最多展示 3 个有实质差异的方案，不能用重复方案凑数。

### 4.5 执行与重排

- 虚拟时钟推进，不声称持续获取真实 GPS。
- 任务状态：待办、进行中、已完成、已跳过、不可行。
- 用户可注入“门店关闭、路线延误、临时不可达”等情景事件。
- 已完成任务锁定；未完成任务重新规划并展示前后差异：新增/移除任务、顺序、预计回家、余量。
- 所有事件显示“情景模拟”，复位后恢复原方案。

### 4.6 时间空档

输入当前地点、可用分钟数、返回地点、活动类别/关键词。系统计算 `去程 + 等待/服务 + 回程 ≤ 预算`，有营业时间时进行窗口校验。结果卡显示可完成、剩余时间、往返耗时和不可行原因；不能用单程圆形半径代替往返判断。

### 4.7 社区体检

#### 输入与图层

社区中心/地址、5/10/15/20 分钟阈值、居民采样格网、五类设施权重。地图图层包括等时圈、POI、居民格网覆盖率、轻/中/重盲区、疑似路网阻隔、复通带/圈内不可达带。

#### 五类供给

医疗、教育、购物、药店、养老。POI 检索需按关键词表、分页和 UID 去重；结果称“百度可检索 POI”。

#### 体检与处方

- 居民样本点到设施的步行可达率，不与中心等时圈混为同一指标。
- 综合分和分类分，权重在报告中公开。
- 盲区诊断：设施不足、疑似路网阻隔、混合型。
- MCLP 贪心给出新增服务点 1/2/3 个方案，展示新增前后覆盖率和受益格网。
- 新增点为情景假设，必须显示“模拟新增”，不能伪装成真实设施。

### 4.8 历史案例与研究证据

至少展示 3 个资料完整案例。每个案例包括城市/社区、时间、输入数据版本、地图、指标口径、API 调用账本、结论和局限。历史实验数据、实时 API 数据和模拟情景在视觉上分开。

### 4.9 报告、分享与可复现

报告类型：通勤方案报告、独立等时圈报告、社区体检报告、执行重排报告。统一包含摘要、地图快照、指标、来源、假设、警告、原始请求摘要和 traceId。

按钮：打印、下载 Markdown、下载 JSON/CSV、复制本地分享链接、重新计算、复位。报告不得包含 AK 或其他密钥。

## 5. 页面布局规格（供前端生成）

### 5.1 全局 Shell

```text

Nav: 通勤沿途 | 等时圈 | 今天安排 | 时间空档 | 社区体检 | 历史案例
```

### 5.2 地图页通用三栏


状态必须有：首次空态、定位授权中/拒绝、搜索无结果、计算中、部分完成、完全完成、API失败、AK未配置、限流/配额不足、缓存命中。地图上不能仅用颜色表达状态，需有图例和文字。

## 6. 领域状态与数据模型

### 6.1 共用对象

`Place`（名称、UID、坐标、坐标系、类别、营业时间及字段来源）；`Route`（起终点、几何、距离、耗时、方向、来源）；`PoiOption`（可达证据、绕行、服务、营业窗口）；`Assumption`（字段、值、seed、原因）；`Report`（摘要、指标、地图、来源、警告）。

### 6.2 等时圈对象

```ts
IsochroneSession {
  id, origin, originSource, thresholdSeconds[], selectedThreshold,
  status, layers[], report, nearbyPois[], mode, sourceKind, traceId
}
IsochroneLayer {
  thresholdSeconds, polygon, rays, failedBearings, skippedBearings,
  radiiM, pairsUsed, cacheHit, algorithmVersion, warnings
}
```

### 6.3 计划对象

`Task`、`PlanRequest`、`PlanAlternative`、`TimelineEvent`、`ScenarioEvent`。时间全部使用整数秒；百度交互坐标为 BD09，GeoJSON 导出转换为 WGS84；所有几何带 CRS。

## 7. API 与前后端契约

### 7.1 已有能力

```text
GET  /api/health
POST /api/locations/search
POST /api/routes/walking
POST /api/travel-matrix
POST /api/corridor/pois
POST /api/corridor/evidence
POST /api/isochrones
POST /api/plans
POST /api/plans/feasibility
```

### 7.2 需要补齐的产品接口

```text
POST /api/isochrones/pois
  输入：origin、thresholdSeconds、polygon/rays、category、limit
  输出：POI列表、可达耗时、营业时间、sourceKind、warnings

GET  /api/isochrones/{taskId}/report
  输出：报告摘要、边界统计、POI统计、调用账本、来源和警告

POST /api/reports/export
  输入：reportId、format(md|json|csv)
  输出：脱敏导出内容或下载地址
```

`POST /api/isochrones` 响应应补充 `mode`、`sourceKind`、`origin`、`report` 和每条射线的来源/失败原因；前端不得再把所有结果硬编码成 `api-cache`。

### 7.3 Provider 要求

比赛版只实现真实 API provider。服务端缓存仅保存真实百度响应，用于相同请求的去重和配额控制；缓存命中仍保留原始响应 hash、请求参数摘要和记录时间，不构造人工路线、POI 或等时圈数据，也不把缓存称为实时结果。

## 8. 数据、模拟与缓存策略

| 字段 | 真实 API/缓存 | 模拟/用户输入 |
| --- | --- | --- |
| 地址、坐标、POI、路线、距离、导航耗时 | 是 | 否 |
| 营业时间 | 有则使用，无则未知 | 不得静默补齐 |
| 排队、店内服务时长、用户偏好 | 否 | 是，固定 seed 且可编辑 |
| 临时关店、延误、断路 | 否 | 是，标注情景模拟 |
| 新增社区设施 | 否 | 是，标注模拟新增 |

缓存键至少包含数据集版本、请求参数摘要、坐标系、阈值、算法版本和上游响应 hash。所有 API 调用写账本；预算不足时只标记 skipped，不生成假半径。

## 9. 验收标准

### 功能验收

- 能从地图点击、搜索和自定位三种方式创建独立等时圈。
- 能切换 5/10/15/20 分钟，看到叠加边界、POI 和报告。
- 通勤页可选沿途 POI，能计算有向绕行、模拟服务和回家余量。
- 今天安排支持 2–5 个任务、候选、顺序、窗口、执行和重排。
- 时间空档能判断往返可行性并解释无解原因。
- 社区体检能显示五类供给、盲区、障碍和新增点前后对比。
- 历史案例使用仓库中的实验结果；实时分析和报告必须来自本次真实 API 请求或其真实响应缓存，且每项数据可追溯来源。

### 质量验收

- 所有异步页面都有旧请求丢弃/复位保护。
- 真实 API 的成功、缓存命中、超时、限流、AK 无效、无路和部分结果均有可理解反馈。
- 375px 和 1440px 宽度可用；地图图例、键盘焦点和文字状态完整。
- 导出产物无 AK；模拟字段、真实字段、派生字段可区分。
- 当前回归门槛：API、Web 单测与 E2E 全通过；新增功能需要为点选、自定位拒绝、阈值切换、报告导出、AK 缺失、配额耗尽和缓存命中增加测试。

## 11. 比赛演示脚本

1. 通勤沿途：输入公司/家 → 选择药店 → 展示真实路线、等时圈、模拟停留和预计到家。
2. 独立等时圈：切到“等时圈” → 地图点选/定位 → 15 分钟 → 点圈内 POI → 打开报告。
3. 今天安排：把 POI 加入任务 → 增加取件/买菜 → 生成并比较方案。
4. 执行重排：注入模拟关店 → 已完成任务保留 → 未完成任务换店并显示差异。
5. 社区体检：切到社区 → 五类覆盖率/盲区 → 新增养老点 → 前后报告。
6. 在线复位：重新发起真实 API 请求或命中真实响应缓存；所有字段仍有来源说明。

## 12. 重要限制

- “等时圈”表示按当前道路测量和采样重建的近似边界，不是完整道路网络的数学精确解。
- POI、营业时间和路线受百度数据更新时间、权限、分页上限影响。
- 模拟停留、事件和新增设施只用于比赛情景，不代表现实状态。
- 真实 GPS、实时路况、全国覆盖、账号协同和支付属于后续产品，不纳入本比赛版承诺。
