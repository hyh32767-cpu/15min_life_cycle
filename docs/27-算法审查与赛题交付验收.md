## 2. 算法审查结论与修复

### 地图 API、数据清洗和隔离

服务端入口使用具名坐标及 CRS；百度请求统一转换到 BD09。等时圈必须先转换中心，再计算探针，避免中心为 WGS84 而终点被错误标记 BD09。地点/路线/时长/距离来自真实响应或有效响应缓存，合成数据仅用于无网络测试，不参与应用运行。

POI 按 UID 去重，缺 UID 使用名称、位置、地址组合键；几何走廊只用于召回筛选，最终时间使用有向 OD。检索设置页数与唯一条数预算，预算耗尽即标记截断。本轮修复圈内 POI 页预算耗尽却未标截断的问题。百度检索不是现实普查，“未检索到”结论限定于本次地图收录、关键词与范围。

产品适配采用 ContextVar 请求凭据，不修改研究客户端全局 AK/SK；产品上下文不写研究账本，由产品服务记录独立账本。网络重试次数计入产品 liveRequests 和 pairs；缓存读取计 cacheHits。并发凭据隔离、重试与默认缓存命中均有回归测试。

结构化营业时间缺 close 不再推断全天开放；非法小时/分钟不生成营业窗口。明确 shop_hours 文本仍可按实际内容解析，缺失表示未知。

### 等时圈

在线算法为 `m2-ray-bisect-v3`：默认 8 个方向，初始 800m，括界 200–1400m，二分容差 50m，默认预算 64 对。测量使用百度步行矩阵，方向固定；无路径、无效测值、预算不足分别保留失败/跳过信息。预算是实际发出探针的硬上限。算法依赖方向上的前缀可达近似，复杂路网存在非单调可达/复通带；研究版更密集采样和拓扑能力不属于当前在线功能承诺。

分层热力分别测量各阈值，按外层到内层覆盖填色，不用一个边界等比例缩放。partial 不拼接跨缺测方向的整片填色，不输出完整面积/周长；报告半径统计仅计算成功方向。当前不是连续空间插值热力栅格，属于赛题鼓励的扇形采样近似展示。

派生键绑定算法版本、中心、阈值、预算、方向及全部上游响应 hash。本轮修复混合 peek/live 时遗漏 peek hash 的问题；API 缓存与实时响应均纳入依赖，版本升级使旧派生报告失效。API 缓存预检命中可零新增上游请求，报告重取保留 taskId 索引。

### 规划与执行

规划器枚举最多五个任务、每类最多三个候选及满足 precedence 的任务顺序；早到等待、服务结束与关门、最后返程与全局截止均为约束。最快按完成时刻排序，最少步行按真实路线距离排序；缺 OD 不填零、不使用直线估算。可选任务按显式 required 字段处理，不自动跳过必须任务。

独立穷举 oracle 对两个偏好各验证 60 个随机有向小图（seed=20261007）。本轮修复已完成前置依赖未解除、最少步行重排未计真实距离/返程、全部完成后返程、无解执行仍能完成任务等边界。计划/端点变更使旧路线几何、重排和异步请求失效；显式跳过不推进到未访问地点。

多任务采用整体规划，不能相加各单店绕行。地图最终路线逐段来自 direction；某段几何失败时清空整条方案线，不跨缺段画假连接线。执行是用户操作的虚拟时钟与情景事件，不是实时 GPS。

### 社区口径与新增设施

社区评分以用户选定中心为基准，九个采样点间隔 500m；五类每类最多选取最近五家实际检索设施，矩阵计算各采样点步行可达覆盖。柱状图展示分子/分母，综合分只有五类全部完成才显示。若检索截断、网络错误或矩阵 cell 未查明，则不宣称完整评分；明确 no_route 作为不可达。它是“已检索设施的采样覆盖”，不是普查或人口覆盖。

1km 检查使用地理半径，与时间阈值评分独立。1.8km 检索半径覆盖九个采样中心的全部 1km 邻域；某类别完整检索后无附近设施才标缺少；截断/失败时标未知。任意一类确定缺少即可标盲区，并保留其它未知类别。网格颜色描述采样中心结论，不能推断格内每个位置都一致。

新增设施名称/位置为用户提出的模拟设点，通行时间仍使用百度；before 只用原设施矩阵，after 再加新设施矩阵，防止新设施时间污染 baseline。MCLP 建议采用贪心覆盖增益，不宣称精确全局最优。换中心/阈值清除旧统计、图层与在途响应。

## 3. 真实社区对比与成本

哈尔滨道外中华巴洛克历史街区，中心 BD09 (126.64736,45.78763)，历史真实 API 响应分析见 `12-真实社区对比测试报告-哈尔滨道外.md`。五类加权分 94.1；养老原覆盖 73.5%，候选方案在单独 200 点复核样本上覆盖 197/200（98.5%）。两者分母不同，不能直接相减当同样本改善；OSM 教育候选旧址百度复核 8.7%，换址 87%，说明必须以百度矩阵复核初筛。该报告为历史数据重算，报告运行新增调用 0，不是本轮 live 调用。

北京回龙观小区→龙泽苑当前产品闭环见 `acceptance-live.json`：基准 3608s/3984m、119 个几何点、6 个召回候选，计划 ready（18:57:48 完成），关店 infeasible、移除事件 ready。15 分钟圈完整 8 向、48 对、8 次 live 请求，14.24s；重复 0 次 live、0 对。首次链路累计 17 次 live/88 对。这是此前受控成功记录，不被本轮失败覆盖。

本轮社区专项见 `acceptance-community-live.json`：临时缓存/账本，历史研究 calls.db 前后 SHA-256 相同；菜市场与药店 QUOTA_EXCEEDED，小学 4 家。5/10 分钟边界 partial，15 分钟 complete；重复均为 0 live 且半径一致。累计 22 live/131 对/7 错误。随后产品缓存中的三类有效响应允许完成灰色格展示，见 docs/29；它不替代首次 live 验收。

本机五任务×每类三候选，规划 30 次：P50 205.85ms/P95 216.08ms/max 235.35ms。OD 已齐备的纯计算，不能与含网络的首次请求时间混为一谈。

## 5. 外部条件与准确性限制

- 百度 POI 配额受限：三类/五类全部成功的 live 终验及真实新增设施改善仍不能签为完成；错误状态和未知呈现可以验收。
- 固定射线二分依赖前缀近似，存在采样与地图收录误差；没有实地核查，不称现实盲区绝对准确。
- 公开源码托管与远端 CI 未执行；当前仓库历史曾追踪 `.env`，公开前由维护者轮换历史密钥并选择安全发布历史，见 SECURITY.md。本轮不改写历史或推送。
- 当前用户优先级为手机组件和通用路径；P1 多人会合、账号、实时 GPS 等不纳入本轮。
