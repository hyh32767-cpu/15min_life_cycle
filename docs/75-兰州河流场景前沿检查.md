# 兰州中山桥：新前沿尚不能可靠处理河流

2026-10-16，用户要求检查历史实验中跨河的兰州选点。中心为BD09 `(103.82343237129777, 36.0707785613421)`，沿用历史中山桥中心，不另换成更容易的地点。

## 本次运行

100米网格、半径1000米圆盘、15分钟阈值，使用当前`grid-frontier-disk-v2`：共测231个位置、13个算法批次；其中27个来自历史缓存，204个缺失位置由真实百度步行矩阵补测。账本记录9次HTTP、204对、0错误。总过程72.93秒包含发送节奏、网络和展示快照生成，不是全冷启动测试。历史数据库只读，前后SHA256一致；新响应进入正式服务缓存/账本，另存逐点记录。

原有数据只有完整250米大范围网格，100米圆盘并不完整。本轮没有将插值或近邻伪装成API测值，没有全量重测圆盘，也没有追加独立检查API。

## 结果：不能判定通过

未参与本次前沿的741个历史位置用于检查，发现误判可达107个、漏掉可达76个，点级IoU约0.6673。检查数据来自历史时段，和当天补测混合，不能当作同时刻全量真值；仍足以暴露原有河道反例未得到可靠处理。

| 中心相对位置 | 历史真实步行时间 | 当前分析边界 |
| --- | ---: | --- |
| 向东200米 | 1777秒（29.6分钟） | 被推断为可达 |
| 向东400米 | 1604秒（26.7分钟） | 被推断为可达 |
| 向东500米 | 1520秒（25.3分钟） | 被推断为可达 |
| 向西400米、向南100米 | 1143秒（19.1分钟） | 被推断为可达 |

这些位置本轮未测，错误来自内部推断，并非它们被API查询为15分钟以内。算法能看到部分向内延伸的不可达通道，但目前外部前沿遇到可达点就停止；深内部默认推断可达，少量固定抽检没有扫到`y≈0`的细长河道。此案例没有形成内部洞，河流缺口被填过头。

需要解决的是内部屏障测量策略，而非增加绘图平滑。蓝色三角网拟合只是展示，圆角也只作显示；都不改变本次正式分析的误判。桥梁连通应由真实步行耗时决定，不能把整条黄河两岸简单切成互不可达，也不能将所有夹在可达点之间的位置填成可达。
