# 等时圈时间切换与热力层缓存

日期：2026-10-13。用户补充：需要生活圈等时范围自身缓存，时间切换及热力图不应反复请求服务。本文补充docs/41的设施结果缓存，二者分开。

## 当前实现

后端原有原始有向OD缓存和依赖源hash的派生等时圈缓存；前端之前每次时间切换及打开热力图都调用等时圈接口，虽然服务端可能零上游计费，HTTP请求仍重复。

现在等时圈store共用一个结果缓存，以算法参数版本、坐标系、精确起点、时间和64对预算为键。只有完整且时间匹配的结果可保存，部分/失败继续请求。坐标转换后同时登记转换前与响应BD09起点的键；不同地点不会串圈。

时间按钮及热力层都走同一入口。已经完整测过且有效的5/10/15/20分钟范围直接恢复，不请求服务；热力图只补尚未完整测过或已过期的时间层。当前层已知过期时也重新校验，不能仅拿旧显示结果继续填热力。界面标「已复用步行范围」，不把前端复用伪装成服务端账本新增命中。

后端通过只读OD预检及实际矩阵的expiresAt汇总最早源到期时间，派生命中时重新返回原始源到期时间，不续期。HTTP模型保留expiresAt，前端复用沿用共享缓存的10分钟/50项上限且不能超源有效期；到期信息缺失不建立内存缓存。刷新清除页面内存，仍由后端原始/派生缓存校验；这是缓存校验请求，不等于每次都重新调用百度。

## 验证

- 12项等时圈store/缓存相关单测通过，包含过期与部分结果重新请求、过时响应丢弃、有效期不延长。
- 19项等时圈后端服务与HTTP契约通过；新增测试验证派生命中到期时间与原始测值一致且穿过响应模型。
- 6项相关E2E通过，最后补充失效防护后核心圈缓存用例再次通过：15→5→15仅请求900/300秒；热力图只增加600秒；再次打开零请求；切10分钟复用；20分钟首次增加1200秒，已有低时间层全部复用；换地点重新测。
- Lint、类型、构建、健康检查通过，后端重启生效。全程构造业务数据，未新增真实圈/矩阵/POI查询。此前原生窗口定位阻塞没有恢复，不声明原生验收通过。
