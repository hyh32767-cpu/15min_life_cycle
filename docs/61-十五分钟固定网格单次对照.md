# 十五分钟固定网格单次对照

2026-10-16用户同意尝试纯网格，以检验提前生成全部测点能否减少串行依赖。本轮仅进行实验，没有修改或替换线上等时圈算法，没有额外查询设施、路线几何或5/10分钟层。

## 范围与调用方式

- 与视频及固定16向实验共用王府井BD09中心：116.417939,39.915062。
- 固定200米网格，中心周围1400米圆形裁剪，保留149点（含中心）；阈值900秒。最大范围是本次实验选择，不是由15分钟必然推出的服务上界。
- 预先生成全部测点，不做二分或自适应加密。分为6个HTTP批次，每批最多25点、最多2批并行，调用腾讯云正式`/api/travel-matrix`，共用已有缓存、限流与冷却。
- 未清空刚才16向实验的缓存；首次8点复用缓存，因此不能与无缓存16向实验视作严格同条件比较。

## 实测结果

| 阶段 | 耗时 | 结果 |
| --- | ---: | --- |
| 首轮 | 16.820秒 | 78点有效、71点未知；首轮实际可达34点 |
| 仅补71个未知点 | 18.139秒 | 额外取得70点有效耗时；最终148点有效、1点未知 |

首轮有一次百度401，23对失败；冷却影响其他批次，部分返回部分结果，部分因本地排队超时返回503 SERVICE_BUSY。HTTP200也可能包含error单元格，因此不能把首轮16.820秒说成完整网格算完。

补测只请求未知点，没有重测有效点；按每9秒发最多25点、单HTTP并行执行，避免继续抢占窗口。该等待是主动调度的一部分，未修改生产限流器或.env。仅补一轮，不再重复探测。

两阶段之间存在人工查看结果和准备补测的间隔；16.820+18.139约34.959秒只表示两个请求阶段的耗时相加，不是一次连续测试完成时间，也没有计入人工间隔。不能据此宣称固定网格比此前20.230秒的固定16向更快。

两阶段总上游7次HTTP尝试（6成功、1次401），164对尝试，141对成功响应（其中含中心零值），网络响应累计0.756秒；首轮8点原缓存命中，补测再次读取1个中心零值缓存。

最终47个有效点满足步行耗时不超过900秒。最远的已测可达点距中心直线1000米，这是200米采样下的观测，不是精确边界半径。中心自身返回零距离、无有效正耗时，正式服务将其标记error，本实验未伪造成实测0秒。未知点不能作为不可达证据。

固定网格消除了测点之间的算法依赖，但仍受真实路线数窗口、上游限流冷却、本地排队超时约束。200米网格与16向25米二分容差不等精度，也没有生成完整路网图。
