# 外向内前沿与逐批拟合展示

2026-10-16。按用户要求改进算法，从外向内依次进行，提高串行批量效率并在地图上逐批展示；后续明确“按目前点连线拟合即可，与实测分开，只为了动态展示”。已接入本地生活圈，未部署腾讯云，未新增真实百度业务调用。

## 新算法

`core/grid_frontier.py`，版本`grid-frontier-inward-v1`，替代生活圈上一版风险优先AMR/射线采样入口，沿途路径原有射线接口保持兼容。

1. 主圈使用中心±1000米、100米格点。外框80个位置先测完，才进入900米层。每批最多50对，串行调用。
2. 只有真实超时/明确no_route的外侧点推动前沿向邻近未测点推进；可达点终止对应分支继续深入。主阶段严格保持外层半径非递增，不允许小半径阶段重新跳回外层。
3. 同层横向补一格连接保护，避免绕角连续产生1–3对小请求。它是边界连接成本，不做全域子格加密，也不在边界前无条件铺36个内部哨兵。
4. 外部前沿结束后才做最多16个分层内部探针；发现超时缺口再作局部检查。该阶段独立标记为interior-check，不能当成主阶段倒序。少量抽检不能保证所有小障碍/复通带都已发现。
5. 440个外部位置为主圈上限（全21×21网格减逻辑原点），常规在内区停止。失败、未知、预算耗尽均保留partial，不补假秒数或默认半径。
6. 明确no_route与unknown分开；no_route不伪造9999秒或无穷JSON值，边界只能使用格内近似；未知阻止最终区域填色。

5/10分钟继续在主圈后单独测量，复用相同OD缓存。它们使用100米基础格与分别500/900米半宽的研究窗口（15分钟1000米），若可达范围触边则明确标记clipped；这些半宽不是物理速度上界或完整圈保证。

## 串行调度

新任务每次只调用一个≤50对矩阵批次，不并发发多个前沿批。任务间共享串行发送节奏，并继续叠加原BaiduService的全局/接口限流。发送间隔由上一批路线对数决定，采用此前已测档位插值参考：10/1.8秒、20/4.1秒、30/6秒、40/7.2秒、50/9秒，小尾批保留至少1.8秒。已消耗的响应时间不重复等待；完整OD缓存命中不占新增发送窗口。

这些档位来自之前实验，不能视为长期权益或免限流保证。本轮没有新AK实时测速。401/302等结构化上游错误会停止任务继续真实查询，保留已完成测点/虚线并解除前端操作锁，不自动重复整圈。

## 逐批显示与最终几何分离

- 每个批次返回立即发布独立任务快照；首批50个位置就有进度，不等完整圈。后台状态接口沿用原接口，前端轮询更新，不人为延时播放。
- `frontier.samples`是实测/明确no_route/未知位置；测点颜色区分可达、超时、无路线、未知。
- `frontier.previewContours`使用当前有效测点Delaunay时间场拟合，仅用于虚线动态展示；`previewOnly=true`标识该拟合用途。测点不足或未跨阈值时可以没有线，不为了动画造一圈。
- 拟合预览不参与圈内判定、面积、设施覆盖、评分或最终几何。最终返回时清空拟合线。失败时可保留先前拟合，但提示“范围未测完，虚线仅供参考”。
- `reconstruction.contours`仅保留局部实测边的阈值穿越线段，开口不强制闭合；最终`frontier.polygons`作为唯一分类近似几何，保留洞与分离分量；`frontier.fills`使用同源局部三角形绘制，避免填掉洞或引入网格内部描边。
- 前沿完成且无缺测/预算截断后，未测深内部按有限检查下的区域估计填色，记录interiorEstimated及近似说明。任务complete指窗口内本轮前沿/有限检查完成，不代表完整路网或全内区逐点证明；触边保留clipped。
- 新几何版本进入前后端缓存key；原始有向OD缓存继续复用、TTL不续期。只有完整且源expiresAt有效的结果进入派生/前端缓存，预览和partial不缓存为成功圈。cache_only禁止任何上游查询。

设施过滤、25个覆盖采样点、地图填色、面积/周长及报告已经消费同一grid-frontier几何；过滤保留洞及多分量，类别缓存key包含算法版本与完整多边形/洞。JSON报告包含frontier及preview用途标志，CSV输出实测点/状态而非空射线表。原射线响应仍兼容，radiiM不被伪造为新算法分类依据。
