## 依据和根因

后续历史配置复核：E3脚本与JSON记载“50请求/3秒”，E4按50条/批、响应后等待1.2秒执行。进一步发现E3同步循环并未真正产生2/4/8/16QPS，账本实速约0.57—0.61请求/秒；相关并发标定结论已在docs/01标注撤销。当前3条/秒是产品默认值，不是对历史账号权益的确认；历史50/3秒声明亦不能直接当作当前控制台权益。未修改运行额度或新增真实API请求。

已通过浏览器阅读[用户提供的共享聊天](https://share.gemini.google/gOpUIVSHRl1A)，采用明确标记的预估范围先行、后台升级实测、保留功能简化操作的方向。聊天中的赛题断言、历史IoU和完成声明不能替代PDF或代码证据，不据此恢复独立1公里面板或实验过程图层。

三个直接问题：前端没有传`l2First`而同步等待整圈；后台轮询仅约12秒；矩阵限流只对HTTP计数。原账本连续多批8条路线后出现401。

[百度批量算路说明](https://lbsyun.baidu.com/docs/webapi?title=routematrix%2Froutchtout)明确配额和并发按最终路线条数计算，步行每批最多50条。[开发者权益](https://lbsyun.baidu.com/solutions/privilege)列出个人开发者批量算路并发3。历史E3单对请求频率不能直接套到多对批次。

## 最终契约

- 正式生活圈：`adaptive=true / l2First=true / tolM=25 / maxPairs=320`，算法`m3-adaptive-batched-v1`。旧沿途v4调用保持原参数，缓存分版本隔离。
- 16向起步，初始/内端/外端探针合批预取，之后同轮二分合批，阶段共享测值和320个唯一探针预算。外括界至少为时间秒数×2米，20分钟不再固定卡在1400米。
- 弦长>200米、径向梯度>12米/度、中间方向97%半径实测超时触发加密；违规方向优先。最多2轮/48向，预留完整二分预算。可选加密未完成保留已测基础轮廓，警告`adaptive_resolution_limited`，不伪造缺测半径。
- 是有预算的近似射线边界，不等同于完整网格/Delaunay时间场，不声称识别全部非单调口袋/内部阻隔或达到历史实验IoU。基础必需方向失败仍partial/failed，不做完整覆盖分析。
- 预估范围为虚线，不参加实测评分、面积和设施覆盖。完整实测基础圈就绪即显示，后台继续补测。地图、报告和社区采样使用同一射线几何，不移动半径或缩放假时间圈。
- 同地点/时间/版本/参数的后台任务合并，最多2个活动任务、128个近期状态，完成任务10分钟清理；最终taskId绑定报告缓存。基础圈完整但加密cache-only缺测时继续后台补测，不能误认为最终缓存命中，也不保存为完整派生缓存。
- `BAIDU_MATRIX_PAIRS_PER_SECOND`默认3，按控制台实际权益调整；拆批不超过该值与50条。线程安全1.05秒成本窗口按路线计数，其余接口默认分别3请求/秒；另有全局HTTP10QPS/4网络槽。同轮最多2批同时执行；依赖上轮的二分探针不提前发出。仅保证单服务进程，多进程共AK需另行统一调度。
- 部分矩阵失败保留结构化`errors`。401按冷却时间至多补一次，已成功OD通过有效缓存复用。鉴权/额度不持续重试，异常不泄漏内部消息。过期数据仍不参加实测。
- 前端最长约4分半轮询，连续3次错误恢复操作并保留已测范围；后端测量回调检查180秒停止期限，当前矩阵批次仍等待完成/超时。主圈生成时禁止启动时间分层；分层复用后台和结果缓存，超时明确提示。
- 地图定位提示5秒消失，可手动关闭；浏览器没有执行定位回调时8.5秒兜底恢复按钮，晚到位置不再移动地图，切页/卸载清理提示。

## 真实验收

只测公开地标王府井商业街同一个15分钟圈，依次复现、复用缓存补齐、最终补齐；没有城市扫点或QPS压测，没有读取设备GPS，没有查询七类设施。

账本5152—5255：84次真实HTTP尝试、313条路线成本，其中初次401批次6条；另307条成功测值。最终31向、307个唯一探针，在320预算内，报告版本与地图一致，警告`adaptive_resolution_limited`。最终补齐阶段27次请求/79条路线、零401。03:06:31—03:08:05约94秒是**带缓存的补齐耗时，不是冷启动基准**。

本机系统代理下API出现约5.2秒响应，也有约0.2秒响应。只读DNS约0.006秒；无配额的百度官网入口同样约5.2秒，直连失败，未绕过代理或TLS校验。不能承诺冷启动几秒完成实测。

Computer Use已确认真实百度地图、预估→实测→完成、390×844手机布局。完成后再次点15分钟显示“已复用步行范围”，最大账本ID仍5255，零新增调用。验收结束为原七类服务偏好，未自动查询。手机截图：`/tmp/shunshou-adaptive-mobile.jpg`。

自动测试均用临时库、SDK和API替身，覆盖凹槽加密/预算/缺测、路线成本时间窗、任务合并/报告绑定、部分401补齐、2批并发/索引对应、缓存基础圈继续加密、长轮询/失败保留结果、定位无回调兜底/提示消失，以及最终完成才一次联动设施。最终测试数量见TODO N35。

最终结果：后端206项（8.80秒）、前端118项、浏览器50项（12.5秒）、纯算法预检11项全部通过，Lint、类型和生产构建通过。并行执行测试时规划性能门槛曾测得P95=1336ms；不放宽原1000ms门槛，待浏览器/前端测试结束后单独运行全量后端206项通过。修改期间热更新曾干扰2项浏览器用例，源码稳定后整轮50项通过。
