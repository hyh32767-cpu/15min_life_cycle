## 四、8 向起步可行性(成都 vs 哈尔滨,射线上限锁死 8)

| | 成都·九眼桥 | 哈尔滨·道外 |
| --- | --- | --- |
| 8 向二分成本 | **0 对**(轨迹前缀性+缓存:tol50 序列 ⊂ tol15 序列) | 0 对(同左) |
| mid 探针 | 1 条轻度违规(22.5°,952s) | **4 条未修复违规(925–1075s)** |
| 8 向 vs 成品边界Δ | 8.2m | 9.3m |
| 结论 | ✅ **可行**(1 条轻度,加密 1 向即可) | ❌ **不可行**(4 扇区留幻影) |

> v5 补充:上表"不可行"指 8 向**不加密**。改用弦规则加密后,哈尔滨 8 起步 → 42 向收敛
> 到 16 起步同形多边形,实际 212 对,仍低于 16 起步的 268 对——"8 起步 + 弦规则加密"
> 十城全面占优(见下节与 docs/08 第二节)。

### 判据的重要发现:F1 会说谎,mid 探针才是照妖镜

哈尔滨 8 向均匀 F1(0.971,格点口径)**反而高于** 自适应16起步(0.957)——加密多边形对
局部 API 细节过拟合,8 边形更平滑,而粗评估格点看不见窄条幻影;当年 e10_8ray 实测的
4 条 mid 违规(925–1075s 的口袋)只有探针能暴露。**→ "8 向是否可行"不能看分类指标,
必须看弦/mid 探针违规数**(v5 弦规则加密正是把该判据直接做成了加向触发器)。

### 生产线最终参数(v5,取代初版"64/256 对"两档估算)

```text
起步 = 8 向均匀 × tol50(轨迹前缀性 ⇒ 与 16 向口径重放零成本)
加密 = 弦规则:扇区内实测超时点落入当前多边形(违规)或 θ≥30° → 弦中点方位插向
实测 = 自适应8起步 104–212 对(十城),全部低于 16 起步 128–295 对(长沙 140 vs 295)
收敛 = 十城全部收敛到 16 起步同形多边形(k=16~42,k 即城市难度;哈尔滨 42 最难)
判据 = 弦/mid 违规数,不是 F1
```
