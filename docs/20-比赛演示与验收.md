## 1. 8 场景入口

| ID | 场景 | 前端入口 | 后端支撑 | 当前状态 |
|---|---|---|---|---|
| S00 沿途挑店 | 公司→家基准路线 + 沿途 POI 候选 + 按需等时圈(5/10/15,最多3圈对比) | `/`(通勤沿途) | `POST /api/routes/walking`、`POST /api/pois/corridor`、`/api/pois/corridor/evidence`、`POST /api/isochrones` | 可操作；需联网并配置百度 AK，所有路线/POI/测时来自真实 API 或其响应缓存 |
| S01 下班办事 | 固定取件 + 任选买菜 + 沿途药店，任务编辑器整体规划 | `/plan`(由通勤卡“固定这家店/同类任选”带入) | `POST /api/plans`(2—5任务、固定/任选/precedence/时间窗) | 可操作；编辑停留/依赖后真实重算 |
| S02 时间空档 | 接人前预算内往返可行性 | `/explore` | `POST /api/explore/check` | 可操作：预算/服务滑杆+往返检查，超预算判 OVER_BUDGET、缺路判 NO_ROUTE |
| S03 临时关店 | S01 首任务完成后注入模拟关店 | `/plans/:id/run`(执行页) | `POST /api/replan`(锁定已完成，候选层替换) | 可操作：执行页虚拟时钟+完成锁定+关店事件+重排前后对比 |
| S04 路线延误 | 未完成路线注入模拟延误/不可用 | `/plans/:id/run`(执行页) | `POST /api/replan`(派生 OD 叠加延误) | 可操作：同上，延误目标 from->to 或 placeId |
| S05 时间不足 | 缩短 deadline/延长服务 → 无解解释 → 放宽恢复 | `/plan`、`/plans/:id/run` | `POST /api/plans`、`POST /api/replan` | 可操作：无解原因+放宽建议显示，不自动删必须任务（T212 映射以 planner 实际 reason 为准） |
| S06 社区改善 | 添加养老点看覆盖/盲区/分数联动 | `/community` | `POST /api/community/coverage` | 可操作：阈值覆盖+盲区+新增点 delta；新点为模拟假设，可撤销恢复 |
| S07 历史证据 | 哈尔滨/桂林/兰州三案例图、指标、来源 | `/cases` | `GET /api/cases`、`/api/cases/{id}` | 可操作：案例列表/详情往返；历史与模拟分开标注 |

路由定义见 `web/src/router/index.ts`；API  surface 见 README 端点表。

## 2. 讲稿(3 分钟，按 S00→S01→S03/S04→S02→S06→S07)

- 0:00—0:45 S00 沿途选店：在 `/` 输入公司/家并确认候选，取基准路线；候选卡按“实际矩阵Δ/到家/余量/营业未知/来源”排序；点一家 POI 看 5/10/15 分钟 API 测时圈(接入/返回点 + 橙色绕行线)。话术：“路线、耗时、距离来自同一百度响应；圈是百度步行耗时测出来的，不是圆。”
- 0:45—1:30 S01 下班办事：候选卡点“固定这家店/同类任选”带入 `/plan`；设出发/截止/停留/先后依赖，整体规划返回方案卡 + 时间线(每段有来源)。改停留时间，方案、到家、余量同步重算。
- 1:30—2:05 S03/S04 关店与延误：执行页虚拟时钟完成首任务后注入模拟关店/延误；已完成锁定，未访门店替换；事件标“情景模拟”，基础路线保留 API 来源。
- 2:05—2:25 S02 时间空档：拖预算滑杆，往返办不完的点被排除；“单程可达 ≠ 往返可行，方向不假设对称。”
- 2:25—2:45 S06 社区改善：加一个养老点，覆盖率/盲区/分数联动，可撤销恢复；“新点是模拟假设，老设施与通行时间仍是 API 数。”
- 2:45—3:00 S07 历史证据：`/cases` 看哈尔滨/桂林/兰州；“这是历史实验，不是新功能准确率。”

> 未实现环节一律说“该环节尚未实现”，不演示、不展开。

## 4. 已知限制

1. 比赛版不提供离线回放；百度 AK 无效、限流、超时或无网时，页面必须显示明确错误，不能生成假路线/POI/等时圈。
2. Playwright E2E 已 6 项通过，但全部是 route-mock，仅验证前端交互，不替代真实百度 API/AK 的 live 验收。
3. T110 地图仍为 SVG 占位：`web/src/components/map/RouteMap.vue` 为纯 SVG 投影
   (路线/绕行线/测时多边形/接入返回点)，非百度底图；独立等时圈入口、阈值切换和
   报告已接入，但空白地图点选、自定位坐标转换仍需补强。
4. T212 无解原因映射以 planner/replan 实际 reason 为准（NO_ROUTE/DEADLINE/CLOSED 等+放宽建议），无独立映射层；T211 时间线来源在方案卡/时间线逐项显示 sourceKind，点击弹窗待补。
   T310 持久化已实现（stores/persistence 版本=1，快照/恢复/复位）；T311 键盘操作与完整状态徽标覆盖待补。
5. 密钥通过服务端环境变量或本地 `.env` 注入（变量名 BAIDU_MAP_AK/BAIDU_MAP_SK）：
   公开前必须迁移并扫描；发布包构建绝不复制仓库根目录，
   以 `api/`、`web/dist`、`demo-data/v1` 为候选并经
   `tools/demo/scan_release.py` 检查。
6. 收益数字口径：规划 P50/P95 为合成 OD 纯计算基准(见上)；live 等时圈单射线实测
   (6对/status=complete/半径706.25m)引自 TODO 历史记录，未在本轮重测；
   其他“省时/覆盖率提升”类收益数字本轮未测量，一律写“待重测”，不引用、不推算。
