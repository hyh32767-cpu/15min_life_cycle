# 地点搜索与地图选点整改

日期：2026-10-13。工作源码：`/Users/heyh/projects/15min_life_cycle`。

## 问题归因

这批基础交互问题主要属于实现不足。旧社区搜索丢弃地点名称和地址，只留下坐标；地图点选没有待确认标记和地址解析，各页面各写一套表单，状态和错误处理不一致。“今天安排”仅在已有任务时显示，用户无法从这个入口添加第一个地点。不能把这些问题归因于 API 额度。

对照高德开放平台的[搜索能力](https://developer.amap.com/product/search)与[逆地理编码流程](https://developer.amap.com/api/javascript-api-v2/guide/services/geocoder)，输入提示、名称/地址结果及坐标转地址是基础能力；[百度逆地理编码](https://lbsyun.baidu.com/docs/webapi?title=reverse_geocoding%2Fguide%2Fwebservice-geocoding-abroad-base)同样支持坐标转地址。当前凭据已真实验证能取得地址。本轮没有直接使用高德 App 做并排操作比较，也没有声称达到完整高德产品体验。

## 最终行为

- 删除 `plan-panel__task-detail`、候选高级列表和其中的依赖编辑控件；保留已有任务数据的规划约束。原“高级约束与手动地点”改成“添加地点”。今天安排零任务时也可进入。
- 起终点、我的地点、安排任务、社区中心、模拟新增设施位置共用 `PlaceSearch`。保留 API 名称、地址和坐标；修改关键词立即清理旧结果，700ms 停顿后自动查询，支持手动搜索、重试、空结果，并丢弃过时响应。单字输入仍可显式搜索。该自动查询复用现有地点检索，不冒充百度专用 Suggestion 接口；没有热门/个性化推荐。
- 地图选点显示“所选位置”标记，地址解析后出现底部确认卡，可修改名称、确认或取消。等待期间不能提交；解析失败则显示错误，允许填写名称后保存用户输入的精确位置，不编造 API 地址。
- `/api/locations/resolve` 通过服务端逆地理编码、原有缓存和账本取得真实地址；WGS84/GCJ02 在统一出口转 BD09。选中的坐标保持原选点，不吸附到响应中的附近地物。未延长缓存 TTL。
- 显式选点时隐藏下方面板内容，扩大地图空间但保留表单实例。安排确认或取消选点后返回表单，保留名称和停留草稿；离开通勤页不重新弹出安排。页面各自保存已选坐标，避免全局临时槽被其它功能覆盖。
- 社区新增“地图选位置”入口。确认只设中心，不自动测圈。起终点选择与收藏分开，不自动写入地点库；我的地点提供“保存当前起点/终点”。地图创建保存地点仍需确认。

## 与完整高德体验的边界

本轮补齐统一搜索、地址确认、选点标记、取消返回、草稿保留和显式保存。仍未提供高德式搜索历史/热门建议、个性化排序、拖动中心针配合附近 POI 候选列表等完整体验；这些涉及产品实现及数据能力，不能宣称已经相同。当前搜索结果、地图细节与地址颗粒度取决于百度实际返回，失败和配额受限继续明确显示。
