# `code_artifact.html` 与当前 Web 实现：视觉差异审查

更新：2026-09-22。本文基于本地启动 `web` 后的 390×844 截图，与 `code_artifact.html` 同尺寸截图对照；P0 壳层/通勤首屏和 P1 的基础卡片密度、地图控件、社区实时摘要卡/五类供给分项/MCLP 处方已落地，1440px 人工验收已完成，后续只剩气泡详情等增强交互。

## 结论

当前效果差别大，不是单一颜色或间距问题，而是三件事叠加：

1. **运行链没启动完整**：本次只启动了 Vite `5173`，没有启动 API `18080`。Vite 将 `/api/maps/config` 代理到未监听的 `18080`，浏览器收到 `HTTP 502`，因此百度底图、健康状态、路线和 POI 全部为空。这是首要阻断。
2. **页面的信息优先级反了**：当前 `CommutePage` 把公司/家/类别/时间/预算/服务/排队的完整表单放在面板首屏；原型首屏是“基准路线卡 → 类别 chips → POI 卡”，输入应是折叠的编辑入口。当前页面即使有 API 数据，也会先看到长表单而不是原型的候选卡。
3. **原型是视觉产品壳，当前是功能调试壳**：当前组件使用基础边框、原生表单控件和文字 emoji，原型使用深色状态栏、品牌头、地图操作按钮、轻量卡片、徽标、图标、底部抽屉和状态色。需要重排组件和 CSS token，不能只调几个 `border-radius`。

## 当前截图中确认的问题

### A. 先修运行条件，否则无法判断地图视觉

截图顶部出现“百度底图不可用：HTTP 502”，不是百度 SDK 已加载但画不出来，而是 `/api` 反代目标没有服务。当前 Vite 配置把 `/api` 代理到 `127.0.0.1:18080`；`curl http://127.0.0.1:18080/api/maps/config` 也无法连接。

本地完整启动应分两个终端：

```bash
# 终端 1：后端，读取根目录 .env 的 Server AK/SK 和浏览器端地图 AK
make api-run

# 终端 2：前端，/api 代理到 18080
make web-dev
```

另外，百度底图还需要单独的浏览器端 AK；`VITE_BAIDU_MAP_AK_BROWSER` 或 `/api/maps/config` 必须返回 `configured: true`。它不能用 Server AK 代替。没有浏览器端 AK 时应显示“未配置浏览器端 AK”，不是把它误认为普通业务 API 失败。

### B. Shell 结构与原型不一致

原型从上到下是：

```text
深色时间/状态栏 → 品牌标题栏 → 地图（约 30% 高度） → 圆角底部抽屉 → 三项移动/四项桌面导航
```

当前 `AppShell.vue` 的问题：

- `shell__status` 只有“顺手 / SHUNSHOU”，没有原型的 18:15、星期/场景、全屏、撤销等状态信息（见 `AppShell.vue:81`）。
- 没有原型中的品牌图标和标题行，`shell__titlebar` 只有页面副标题和“调用账本”（`AppShell.vue:109`）。
- 底部导航已收敛为 3 项移动主入口（通勤沿途、社区体检、时间空档）和 1 项桌面二级入口（历史案例）；独立等时圈不再占用主导航，案例也不与移动主功能争抢空间。
- 当前状态错误在地图下方再显示一遍，形成红色双提示；原型是地图内轻量状态，不占用主内容高度。
- 当前 `.shell` 默认 `max-width:480px`（`AppShell.vue:238-247`），桌面端再改成双栏；原型是以 390px 移动端视觉为主，但桌面投屏应保持同样的地图+抽屉层级，不能变成普通表单后台。

### C. 地图不是主要视觉失败，数据和容器都要修

当前 `GlobalMap.vue` 已使用百度地图 JSAPI 适配器，但有以下问题：

- API 未启动时整块背景为灰色，原型底图仍占据主视觉；应使用独立的地图 loading/SDK error 状态卡，避免灰色空洞把内容压下去。
- `useGlobalMapLayers.ts` 用 `polygonFromRays()` 从半径重建圈；要检查该函数是否只适用于展示近似圈，并把失败/跳过方向的警告传入图例，不能把部分结果画成完整无缺的绿色面。
- 图层目前统一蓝色路线、三色圈和通用 marker，缺少原型的公司/家/POI/当前位置层级、右侧定位/图层/报告按钮和选中 POI 的黑色信息气泡。
- `GlobalMap.vue` 现在只保留兼容旧引用的薄封装，实际生命周期、点选确认、控件和覆盖物统一由 `BaiduMap.vue`/`baiduAdapter.ts` 负责；后续新功能不得再往 `GlobalMap` 写第二套实现。
- 地图点选应随社区体检启用；等时圈已并入社区体检首段，原型里的选点/定位控件需要在社区页明确展示“点选换点/定位”操作，不要只依赖用户点击空白地图。旧 `/isochrone` 仅保留兼容详情入口。

### D. 通勤页的内容顺序完全相反

当前 `CommutePage.vue:80-245` 首屏渲染完整编辑表单，导致在 390px 视口中候选卡需要滚过很长距离才能看到。原型首屏直接呈现：

- 基准路线卡（公司→家、32 分钟、截止时间）；
- 横向类别 chips；
- POI 候选卡（营业信息、绕行、预计到家、余量、加入安排）。

改法：

- 将地址、出发、截止、预算、服务、排队迁入“编辑通勤条件”抽屉，默认收起；已有确认地址/重新计算按钮保留在基准路线卡右侧。
- `baseline` 放在 sheet 第一块，`chips` 第二块，`poi-list` 第三块。加载前显示原型尺寸的空态卡，加载中显示 skeleton，不显示一长串表单。
- POI 卡采用原型的两行信息层级：名称/类别/营业状态，右侧“+X 分钟绕行”；第二行预计到家/剩余；底部来源和“加入今天安排”。现有字段已大体齐全，主要是布局重排和缺失状态处理。
- 类别 chips 不应只在当前单类别不匹配时显示 0 个候选。若当前响应只有一个 category，点击其他 chip 应触发新 taxonomy 搜索或明确提示“未加载该类别”，不能静默变成 0。

### E. 其他页面是功能编辑器，不是原型面板

- **等时圈（已并入社区体检）**：社区页首段承载起点搜索、定位、地图点选、阈值、指标和圈内 POI；地图先展示圈，结果抽屉展示真实报告。旧 `/isochrone` 仅作为兼容详情入口，不再出现在主导航。
- **今天安排**：当前先显示一个“到家未知”的状态卡，再显示完整编辑器；原型先显示“19:14 到家/余量 +16 分钟”、事件按钮和紧凑任务时间线。没有计划时应显示创建任务入口空态；有结果时隐藏大段编辑表单到“编辑计划”。
- **社区体检**：现在由“等时圈体检 → 综合 scorecard → 五类分项 → 盲区诊断 → MCLP 处方”组成完整入口；数据仍需真实计算，但展示组件必须按原型分成 scorecard、diagnosis、prescription 三块。
- **时间空档**：当前先显示公式解释和三个输入框，原型先显示预算 chips、当前位置/返回点和结果卡。预算/服务/等待应收进“调整条件”，结果优先。

第二轮后：预算 chips、起终点与结果区已保持在首屏，输入区压缩为同一控制行；社区体检现在把等时圈控制与圈内 POI 放在综合诊断之前，社区和等时圈先展示卡片化结果/空态，避免工程表单撑满视口。社区当前展示由覆盖结果派生的实时摘要（覆盖率、设施数、采样格、盲区、阈值），并可并发检索医疗/教育/购物/药店/养老五类真实 POI 与有向矩阵；改善处方只基于 before/after 真实结果给建议，不能填入原型中的静态示例分数。

## 改造优先级

### P0：先让“看到的东西”正确

1. 启动并验证 API + JSAPI AK：`/api/health`、`/api/maps/config`、地图 SDK 加载均通过；记录失败原因区分 502、未配置 AK、Referer 校验失败。
2. 收敛地图实现：删除/停用重复的 `GlobalMap` 旧实现，只保留一个百度地图适配器；补地图内控件、图层图例、选点确认、定位入口和错误占位。
3. 重做 `AppShell`：深色状态栏、品牌标题栏、地图与抽屉高度、3 项移动/4 项桌面导航；案例/账本为二级入口。
4. 重排通勤页：表单收起，基准路线→chips→候选卡成为默认首屏。

已落地（2026-09-22 第二轮）：地图正式统一到 `BaiduMap`/`baiduAdapter`，旧 `GlobalMap` 只保留薄封装；POI 使用短编号气泡避免长名称遮挡，社区覆盖/盲区采样格以真实结果叠加到地图；地图增加缩放/图例控制；等时圈指标改为三列紧凑卡；计划页把结果区提到编辑器之前；空档、社区、计划卡片统一浅色渐变、圆角、阴影和紧凑字号；社区五类供给并发检索并用有向矩阵计算，MCLP 1/2/3 点处方用真实候选坐标贪心排序。第三轮将通勤沿途与今天安排合并：POI 卡直接进入今日安排摘要/整体规划，`/plan` 保留为约束与执行详情页，底部主导航不再重复展示“今天安排”。以上改动不改变真实 API、缓存来源或规划计算语义。

### P1：补齐每个 tab 的原型信息层级

5. 等时圈：地图层优先，origin/阈值为紧凑控制卡，指标和圈内 POI 使用原型卡片。
6. 计划：方案成功时显示到家/余量/事件/任务时间线；编辑器变成可展开抽屉。
7. 空档：预算 chips + 当前地点卡 + 结果列表；编辑参数折叠。
8. 社区：scorecard、五类分项、盲区诊断、MCLP 处方四块。没有住户数据时显示新增覆盖采样格，不显示户数。

### P2：视觉细节和响应式

9. 建立原型 CSS token：`#0f172a` 状态栏、蓝/绿/紫/橙语义色、卡片阴影、16px/12px 圆角、10–12px 辅助文字、统一 badge/chip/button。
10. 用 SVG/自制图标或已锁定图标库替换 emoji；不把 emoji 当作图标系统。
11. 移动端 375/390px 验收底部导航、抽屉滚动和地图操作；桌面 1440px 验收地图主视觉和左/右面板，不把所有字段强行平铺。

## 建议的组件重排

```text
AppShell
├─ StatusBar（时间、场景、API状态、复位）
├─ BrandBar（Logo、页面标题、账本/报告）
├─ MapViewport（百度底图、控件、图层、图例、选点态）
├─ BottomSheet
│  ├─ SheetHeader（标题、可行数、展开/收起）
│  └─ FeaturePanel
│     ├─ CommuteSummary → CategoryChips → PoiCardList
│     ├─ CommunityHealth
│     │  ├─ IsoOrigin → ThresholdChips → IsoMetrics → PoiCardList
│     │  └─ Scorecard → CategoryCoverage → BlindSpot → MclpPrescription
│     ├─ PlanSummary → ScenarioButtons → Timeline
│     └─ GapBudget → GapResults
└─ BottomNav（5 主项）
```

现有 stores、Provider 和算法尽量复用；变化重点是视图层的状态投影和布局，不要为还原原型重新写一套静态数据。

## 验收方式

- 先在 API 在线且浏览器端 AK 正确时截图，再评估视觉；API/SDK 未启动的灰色地图截图不能作为 UI 对比基线。
- 每个 tab 在“有结果”和“无结果”各有一张对比截图；有结果必须使用真实/route-mock 返回，不能恢复 HTML 常量。
- 390px：地图约占上部 30%，底部抽屉覆盖主内容，导航固定底部；首屏应先看到基准/指标/候选摘要而不是完整编辑表单。
- 1440px：地图仍是主视觉区域，控制和结果为侧栏/抽屉；不得退化成窄 480px 页面居中。
- 关键功能链：通勤选 POI→加入安排→规划→事件重排；等时圈点选/定位→真实圈→圈内 POI；空档预算→往返可行；社区计算→五类分→盲区→MCLP；每一步的地图、卡片和时间线同源。
