## 核心发现:OSM 真值的适用性分层(最重要的方法论结论)

**双仪器一致性决定 OSM 能不能当"真值"用**:

| 分层 | 社区 | OSM 数据质量根因 | 结论 |
| --- | --- | --- | --- |
| 高一致(r≥0.87) | 王府井、上下九 | 老城路网密集、开放性好 | **可作绝对真值**:方法 F1 0.94–0.96、边界 Δ64–100m |
| 中一致(0.8左右) | 东花市、九眼桥 | 二环天桥/跨河桥映射口径不一 | 参考仪器:②的下降主要反映 OSM 偏差而非方法误差 |
| 低一致(r<0.35) | 陆家嘴、道外 | CBD 封闭街区+跨江碎片化;棚改区路网滞后 | **只能当第二意见**:分歧本身是信号(见下) |

**道外的悖论很有讲头**:r=0.309(时间值几乎不相关)但绝对精度 F1=0.933、边界 Δ125m——
OSM 在棚改区整体偏慢(bias −66s)但**圈的形状基本对**。→ 交叉验证要分别看"值一致性"与"形一致性"。

**陆家嘴是反例样本**:OSM 步行网在天桥/封闭街区/跨江处碎片化,最近节点吸附跨江 →
时间系统性爆炸(MAE 275s)、F1 0.676。**此时百度 API 才是更好的真值**——单靠 OSMnx 验证会自我误导。

## 配置优化的地形迁移(回答"48 探针能否通用")

```text
规则老城(A)   :8 向 × 50m  =  48 探针 → F1 0.972
一般地形(成都) :24 向 × 50m = 144 探针 → F1 0.974
复杂地形(哈尔滨):24 向 × 15m = 192 探针 → F1 0.972
```

→ **固定离线配置不可行,必须沿用 E10 的地形感知在线决策**(免费弦差信号起步,复杂才加向)。
另外四城在 OSM oracle 下 F1 上限本身 <0.97(数据质量),说明**优化目标应以 API 实测为准,OSM 只做相对比较**。
