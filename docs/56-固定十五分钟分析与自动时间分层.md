# 固定十五分钟分析与自动时间分层

2026-10-15 用户决策，覆盖此前时间按钮/分层开关和“收藏选择只设中心、不自动算圈”的旧约定。

## 统一流程

原先时间选择改变`thresholdSeconds`和分析范围，分层开关在当前范围之内补小圈。两者技术上可以共存，但用户难以区分“切换分析范围”和“显示多个时间层”，并且20分钟主圈与15分钟生活圈主题不一致。

现在生活圈搜索、地图选点、收藏地点或其他入口设置中心后，CommunityPage按地点和当前页面启动单一流程：

1. `generateLifeCircle()`固定请求900秒主圈，预估/逐轮实测显示和测量锁沿用原契约。
2. 主圈完成后，保留15分钟结果，在`heatLayers`补300、600秒圈；每完成一层即发布，不等三层全部结束才展示。
3. 主结果`result`不被小圈覆盖，`thresholdSeconds`保持900。之后自动执行所选服务分析；手动重新分析入口保留。
4. 删除5/10/15/20分钟选择按钮、20分钟显示、时间分层开关和独立热力加载按钮。面板中的三个颜色文字仅说明图层，没有点击行为。

## 显示与分析契约

- 时间层仅5、10、15分钟，从外向内绘制15→10→5，蓝`#3975ed`、青`#39afa7`、绿`#17b684`。外圈主线3px、内圈2px，透明填色参考用户原型；不改变实际测量边界或用视觉样条增加面积。
- 主圈、原始OD和前端结果缓存照常复用。同一中心三圈未过期时，再次选择不新增圈HTTP请求。新中心最多启动三个圈任务，**一个圈任务内部仍可能包含多批百度矩阵请求**，不能称为仅三次上游调用。
- `circleRing`只接纳完整900秒主圈。设施圈内筛选、覆盖采样、盲区、建议、平均覆盖和图表固定900秒；社区评估缓存key、报告阈值和文件名显式15分钟。
- 报告`isochrone`为15分钟主结果，`charts.timeHeatLayers`只携带300/600/900秒层；小圈的失败状态不得替换主圈或伪造完成层。
- 15分钟失败不启动小圈/设施分析，终态解锁并提供“重新生成生活圈”；不自动循环重试。小圈失败保留已完成15分钟层与分析依据，提供“重试加载范围”，只通过缓存补缺层。
- 地点改变后失效旧请求/分析；坐标转换引起的内部origin更新在忙态中不重复启动。生成结束时继续校验请求序号，旧主圈不得为新中心补层。

## 验证

- 153项前端单测通过：新增固定900秒主结果、三个缓存共用、重复生成零新增请求、小圈失败保留主圈/重试补缺层、主圈失败不查询小圈。
- 16项当前流程浏览器检查通过：自动三圈及颜色顺序、全部分析请求900秒、下载JSON主结果/阈值/图层一致、换中心后返回缓存复用、失败显式重试、逐轮轮廓、测量锁/错误解锁、手机/桌面尺寸、设施联动、收藏和路线功能。
- 相关旧时间按钮测试已改为选点自动触发，并保留原请求计数/几何/锁定断言。其余依赖已删除全局PlanBar等入口的历史E2E不作为当前验收证据。
- ESLint、类型/生产构建通过，Computer Use核实正式手机页面无时间按钮和分层开关。全圈与失败验收使用构造API及SDK替身；本轮没有新增真实业务查询、冷启动整圈或部署腾讯云。
