# 节省额度验收与最终差额

日期：2026-10-12。用户要求源码/Git/公开发布最后处理，先补其它验收，避免大量 API 测试。本轮没有提交、推送、公开或改写历史，也没有重新打包冒充最终源码版本。

## 本轮改动

- 社区覆盖采用有向测值的 OR 提前结束：某格已有一家实测可达设施，停止该格其他候选；未覆盖必须测完候选，缺测保留未知。每类候选仍最多五家、九格和权重不变；距离仅用于候选顺序，不替代耗时。40 组小图与完整矩阵 oracle 一致。
- 新设施比较和选址建议只测原本未覆盖的格；全覆盖时不发无增益的建议矩阵。原基线保持独立，不以新设施数据改写 before。
- 修复持久化恢复触发 watcher 重算的问题；在社区页恢复保存的通勤，不再额外算路和检索。恢复结果的来源仍是原有保存状态，不称本次新 API 成功。
- 搜索/地图选择社区中心后，只设置中心；点时间按钮才计算等时圈。选中心做设施体检不再顺带花费一圈的探针。定位由于需要转换 WGS84，保留原流程。
- 独立有限额验收入口 `tools/preflight/economy_server.py`，实际 HTTP 尝试计数、禁止网络自动重试、同接口配额/限流时暂停；重启 `--resume` 保留累计已用额。它是本地验收工具，不是产品运行默认限额。

## 新增 API 使用

预算先设 20 次请求/100 个成本单位；发现恢复意外触发通勤重算，且旧 E2E 对未配置接口直接 `route.continue()`，候选证据请求漏到真实后端。已修复恢复重复重算、补齐构造响应，并将未配置接口改为明确 501，新增隔离测试，不能再放行外呼。累计请求上限调整为 40，总成本仍上限 100，未重置已用额。API 原始缓存全部已过期；没有延长 TTL，也没有将历史库灌入产品缓存。

实际 **36 次 HTTP / 96 个成本单位**，含所有成功、401 及被重算消耗的请求；按接口明细见 `acceptance-economy-budget.json`。成本单位中矩阵对和检索/路线请求分开解释，不能把 96 都说成独立路网测时对。百度 JSAPI 底图请求另属浏览器地图服务，不在产品业务账本中。

代表性真实改善见 `acceptance-economy-improvement.json`：复用本轮九格到一家真实现有设施的测值，基线 8/9；三个用户假设施工位置只新增 **三对** 百度步行测时，耗时分别 0/191/36 秒，新增后 9/9；1/2/3 候选在这个只有一个未覆盖格的样例均增益 1，额外点不增加覆盖。重复相同矩阵命中缓存。这个限定单设施样例不是全五类、全社区或人口覆盖验收；假设设点不是声称当地真实存在新设施。

本轮真实五类界面完成养老 0 家/0 覆盖的确定空结果；其他类别 POI 检索有成功响应，但完整测时受 401 和本轮限额停止，综合分保持未知。未为“全部成功”继续扩大预算。新增 20 类 POI 不逐类刷新查询。

## 精度与边界审计：零 API

`acceptance-cached-accuracy.json` 对北京回龙观、成都九眼桥、上海陆家嘴历史数据只读审计，缓存和研究账本 SHA-256 前后一致。

当前八方向算法按精确历史坐标重算三例均有缺探针，返回 partial；没有插值或补网络测量，所以不能给出当前算法完整 IoU。另做历史加密边界仅留八向的形状消融（排除八条射线附近测点），189/198/189 个非均匀缓存留出点的样本 IoU 分别 **0.6929/0.8118/0.7792**。这是历史形状消融，不是当前产品精度、未来真实精度或完整路网准确率。

长路线纯几何样例 17.04km，最多五中心导致最大间隔 4.26km，正反向中心一致。八方向边界会有假覆盖与漏覆盖；圈内不能替代实际有向绕行可行性，长路线未填色不能断言不可达。保孔洞的几何并集只保留已有圈拓扑，不能凭空恢复圈内未测出的道路障碍。该近似限制保留在产品说明与演示中。
