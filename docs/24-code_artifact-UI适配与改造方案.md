# `code_artifact.html` UI 适配与改造方案

更新：2026-09-22。范围：以本地 `code_artifact.html` 的视觉布局和地图交互为目标，对照当前 `web/`、`api/` 规划改造；本文不表示页面已经接入。遵循 [产品方案](18-比赛版产品与实现方案.md)、[算法契约](19-比赛版算法流程与开发契约.md) 和根目录 `AGENTS.md` 的纯 live/混合数据原则。

## 结论

**业务能力可以承接主要 UI，原型不能直接接入，也不能按现有数据原样展示。** 当前 Vue 应用已有通勤沿途、社区体检（含等时圈模块）、计划、执行、空档、历史案例的页面和相应计算链。HTML 则是独立的 Leaflet/Tailwind/Font Awesome 静态演示：路线、POI、等时圈、评分、报告及按钮结果多为脚本常量。把它直接嵌入会让“实时 API”标签与实际数据不符。

**最新目标是按该 UI 实现，包括可交互街道底图。** 地图适配已按新要求落地：正式地图使用[百度地图 JSAPI 4.0](https://lbs.baidu.com/docs/jsapi?title=jsapi4/index)，`RouteMap.vue` 仅作开发期示意/备用；JSAPI 提供底图、点击事件、标记、折线和多边形，和现有百度 BD09 业务数据更贴合。原型仅作为布局/交互参考，不复制其 Leaflet/CartoDB 底图代码。

## 必须清除的原型假数据与错误语义

1. 删除脚本中的 `COMMUTE_POIS`、`ISO_SERVICES`、`TODAY_TASKS`、`GAP_ACTIVITIES`、固定公司/家/体检中心等运行时数据源。允许保留无网设计稿示例，但不得出现在应用生产路径。
2. 不采用 `renderIsochroneMap()` 的偏移量缩放多边形，以及阈值按钮中 `0.07 × 分钟` 面积、`75 × 分钟` 半径。圈必须取当前任务真实探针结果；面积若由多边形估算，显示“近似”与算法版本，失败扇区须告知。
3. 不把“地图几何接近”“圈相交”“顺路指数 92%”当实际可行性。实际增量用有向 S→P→H 与基准 B；总额外耗时加模拟/用户等待和服务；多 POI 用整体规划结果。若做百分制指数，先定义可解释公式与测试，否则用“额外步行 X 分/到家余量 Y 分”。
4. `shopHours` 为空、状态权限未返回时显示“营业时间未知/营业状态未知”；不能显示“营业中”。“现货充足”“优惠”等无法从现有 API 得到的字段，首版删去，不随意归类为模拟。
5. “圈内 46 家”“覆盖受益 420 户”“综合分 76”“MCLP 推荐点”必须由明确定义的数据集和计算得出；未补实现前显示待计算/错误态，不用常量占位。百度 POI 检索结果统一称“百度可检索 POI”，显示召回截断/失败。没有真实住户数据时不可计算“受益户数”，UI 文案改为“新增覆盖采样格”。
6. 原型 Leaflet 使用 WGS84 地图坐标，但点击提示写“BD09 已映射”；这是错误的。改用百度 JSAPI 后，应用统一采用 BD09 地图输入输出；浏览器定位等非 BD09 来源在唯一适配出口转换，GeoJSON 导出仍转换 WGS84。业务域一律具名 `{lng,lat,crs}`，路线、点、圈、点击与导出分别做 CRS 测试；不得根据数值猜坐标系。
7. 顶栏连接状态、时间、缓存命中、trace ID、调用账本、导出结果须读服务端/场景状态。无法获取时显示 loading/error/未知，不沿用原型固定值；导出按钮收到可下载内容才提示成功。

## 目标结构与交互链

保留现有 Router、Pinia、纯函数 domain 和 `LiveApiProvider`，把 HTML 拆成 Vue 组件；不要复制其全局 JS、`innerHTML` 渲染或 CDN 依赖。建议结构为 `AppShell`（顶栏/导航/响应式面板）、`BaiduMapViewport` 与 `MapAdapter`（百度 JSAPI 生命周期、地图事件、坐标与图层）、五个 feature panel、`ReportDrawer`、`SourceBadge`。地图图层只由各 store 的当前结果投影而来，不另存一套静态路线/POI。现有 SVG 可留作开发/无底图时的明确示意组件，**不可伪装为正式地图或 live API 失败时的假结果**。使用 Vue 文本绑定渲染 API POI 名称，避免把外部字段送进 `innerHTML`。

### 百度地图接入边界

- 使用[官方 JSAPI 4.0 加载器](https://lbs.baidu.com/docs/jsapi?title=jsapi4/guide/concepts/load)在 Vue/Vite 中按需加载地图。JSAPI 负责底图、缩放/拖动/点选、定位入口及 marker/polyline/polygon 等覆盖物；业务 POI、步行路线、矩阵、等时圈采样、规划和报告继续经本项目后端与 `LiveApiProvider`，不在浏览器里绕过服务端账本另算一套业务结果。
- 百度 JSAPI 需要**浏览器端类型 AK**；现有 Server AK/SK 继续只供后端使用，两者不得混用。先按官方建议为浏览器端 AK 配置开发域名和正式域名 Referer 白名单，生产环境不使用 `*`。浏览器端 AK 会出现在加载请求中，不能当 Server 密钥；若要连浏览器端 AK 也不暴露，可按[官方代理模式](https://lbs.baidu.com/docs/jsapi?title=jsapi4/guide/concepts/load)另设 `serviceHost` 与反向代理，不得把 Server AK 拿来充当 JSAPI AK。
- `MapAdapter` 只接受/输出具名 BD09 坐标。百度路线几何、POI、采样圈从 store 渲染成图层；地图点击先放临时 marker，用户确认后才触发可能消耗配额的 API 请求；切页/切阈值清理旧图层及事件监听。浏览器定位坐标在进入适配器前显式转换；导出 GeoJSON 仍为 WGS84。[百度 JSAPI 坐标说明](https://lbs.baidu.com/docs/jsapi?title=jsapi4/guide/concept/coord)
- 地图 SDK/底图加载失败与业务 API 失败分开提示；地图不可用时可显示列表和错误信息，但不能让 SVG 假装仍有可交互百度底图。发布前核对官方地图使用条款、标识展示与浏览器端 AK 白名单。

关键状态链：地址确认 → 百度基准路线 → 走廊搜索与有向矩阵 → 候选卡/地图同源 → 选中 POI 后按需算圈/接入证据 → 加入计划草稿 → 整体规划 → 执行虚拟时钟/事件 → 真实重排 → 报告快照；社区体检入口内再串起中心等时圈 → 五类供给覆盖 → 盲区/MCLP 处方。时间空档和社区体检从主导航进入，等时圈不再单独占一个主导航入口，也不能从通勤 store 借用不合语义的起终点。

数据映射以现有类型为起点：`PlaceRef` 管 POI 名称/坐标/营业字段及来源，`RouteSummary` 管同一次方向 API 响应的线形/距离/耗时，`TravelMatrixCell` 管有向 OD 与单格来源，`IsochroneResult` 管阈值/半径/失败方向/成本，规划结果管 ETA、等待、停留、余量，`CoverageResult` 仅支持采样格数量口径。原型出现而这些类型没有的字段，先判断是否可从百度真实接口补取，再决定省略或扩展契约；不得在前端发明值。等时圈 POI 卡若要显示步行**距离**，须从同一矩阵响应传 `distanceM`；当前契约主要保留 `walkSeconds`，未传距离时只显示时间。

## 实施顺序与完成条件

### UI-0：冻结字段与地图接入准备（半天）

- 对照上述表为每个展示字段标注 `live-api`、`api-cache`、`synthetic-assumption`、`user-input` 或 `derived`，删除无来源的视觉占位。
- 确认浏览器端 AK 已开通 JSAPI，配置本地/正式 Referer 白名单，并对 SDK 加载做最小冒烟；现有 Server AK/SK 不下发。锁定官方 loader 版本，验证 BD09 线路、POI 和圈能在同一地图位置叠加。

### UI-M：百度地图适配（1—2 天，UI-1/UI-2 前置）

- 实现 `BaiduMapViewport`/`MapAdapter`：创建/销毁地图，控制视口、缩放/点击/定位、marker/polyline/polygon、图层显隐、点击候选确认；使用同一 map 实例处理各功能页的图层切换。
- 来源于百度 API 的 BD09 几何不再转成 Leaflet/WGS84 底图坐标；浏览器定位与 GeoJSON 导出依其原 CRS 显式转换。通过位于不同道路的已知点核对图层无偏移，测试切页后不会遗留旧圈、旧 marker、重复事件监听。
- 完成标准：在真实百度底图上完成点选→确认→触发计算，绘制真实路线/POI/等时圈；地图 SDK 加载失败有独立可恢复错误，不回退静态原型数据。

### UI-1：壳层和通勤页（1—2 天）

- 做移动端地图+可滚动/可收合面板、桌面地图+侧栏；五个一级标签与案例二级入口。底部面板拖拽是增强项，先保证键盘和触摸滚动不冲突。
- 接真实健康状态、当前场景虚拟时间、loading/error/empty；卡片从 commute store 映射。类别多选若保留，后端走廊检索请求和成本提示一起扩展。
- 完成标准：选择不同公司/家后基准线、候选、ETA、余量同步变；无 API/超限/无 POI 时不显示原型样例。

### UI-2：社区体检中的等时圈和地图点选（1—2 天，依赖 UI-M）

- 统一起点搜索、定位、地图选点入口；阈值切换必须触发真实测时/有效派生缓存，显示 `complete/partial/failed`、已测方向和请求对数。
- 圈内 POI 和报告用当前 `taskId`；圈不能因切标签残留为别的页面结果。地图层按 route/iso/community/gap 模式明确切换，社区页的等时圈与体检覆盖层共存。
- 完成标准：5→10→15→20 分钟切换有对应真实结果及来源；坐标双向转换通过测试；缺路/配额时不出现圆形假圈。

### UI-3：计划、执行和空档（2—3 天）

- “加入计划”写入 plan store 并显示草稿，提供任务编辑、候选固定/同类、出发/截止、依赖、停留；只有成功规划才显示方案及时间线。
- 执行区复用 `/plans/:id/run` 和 execution store；事件按钮产生明确的模拟假设并调重排，展示前后差异，已完成任务不可被重新排入。跳过必须任务需用户明确接受。
- 空档改独立起点/返回点和 POI 来源，同点返回作为原型默认；预算、等待/服务改动后重算；无路与不满足时间分别说明。
- 完成标准：加 POI、改服务时长、关店、重排时，地图/卡片/时间线同源更新；刷新/复位语义正确。

### UI-4：完整体检、报告与案例（3—5 天）

- 为原型五类设施（医疗、养老、商超、药店、教育）分别做百度区域检索/去重和“居民采样格→设施”的有向步行矩阵；公开采样范围、每类 POI 数、检索截断、格网分母和等权/自定义权重。分类分定义为 `100 × 本类阈值内覆盖格数 / 有效采样格数`，综合分为分类分的权重平均；不可达计盲区，API 错误不伪装为不可达或零分。
- 实现原型的 MCLP 贪心处方：候选新址由用户选点或明确的候选坐标集给出并标记“规划假设”，对每个候选以百度有向矩阵实测采样格步行时间；每轮选最大新增覆盖格数的点，固定 tie-break，支持 1/2/3 点方案并重新计算前后评分/覆盖。用小图穷举 oracle 和单调性测试验证。盲区原因只有在有证据时才写“疑似道路阻隔”，不能由圈形直接认定。
- 原型“+420 户”改为“新增覆盖 N 个采样格”；若未来接入可靠人口/住户栅格，另加住户加权口径和来源，再恢复户数文案。
- Provider 增加等时圈报告重取、导出、账本汇总；综合报告需要新的快照契约，不能拿等时圈报告假装全产品报告。历史案例入口保留且来源隔离。
- 完成标准：五类分、综合分、盲区与处方改善数都能从同一批当前数据复算；报告数字能回溯 trace/响应，导出内容与页面一致；无人口数据时只说“采样格”，不说“户数/居民覆盖率”。

### UI-5：验收与回归（1—2 天）

- Unit/contract：字段来源、未知营业状态、CRS 双向、圈失败扇区、预算单调性、重排已完成锁定、五类评分分母/MCLP 小图 oracle 与覆盖单调性、报告快照一致性。
- E2E（业务 `/api` route-mock，无 Server AK）：五页导航、地图/列表选点、阈值切换、POI 加计划、改任务、执行事件→重排→无解恢复、体检与空档、刷新与复位；地图 SDK 可用独立的测试替身，不把百度外部加载作为离线 E2E 前提；375/390/768/1440px 截图与键盘焦点。
- Live 冒烟（具备浏览器端 AK 与 Server AK）：百度底图加载、点击点位 BD09 对齐、至少一条真实地址→路线→POI→等时圈→计划链；核对 route 几何/距离/耗时同源、调用账本 live/cache 分离、报告和导出。SDK 或业务 API 失败时展示各自错误，不退回静态原型。

## 当前建议

按 **UI-0 → UI-M → UI-1/UI-2 → UI-3 → UI-4 → UI-5** 实现完整原型。五类评分和 MCLP 属于 UI-4 正式范围，不再延期；原型中无真实住户数据支持的“受益户数”改为“新增覆盖采样格”，库存/优惠等无数据字段不保留。当前 T110/地图适配已落地，等时圈已并入社区体检首段；后续验收重点是社区页组合层的 live 体验与报告一致性，不把原型截图当成应用功能完成证据。
