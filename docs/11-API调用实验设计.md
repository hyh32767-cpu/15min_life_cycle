## 1. 总纲

### 1.1 整套实验回答三个问题

| 问题 | 对应实验 | 支撑的评分点 |
| --- | --- | --- |
| **仪器有多准**——路径 API 作为黑盒测量函数 f(o,d)=t 的噪声/偏差/适用边界 | E0、E1、E2 | 功能正确性 40% |
| **怎么调最省**——批量/并发/缓存/重试的最优工程参数 | E3 | API 深度调用与工程优化 30% |
| **算法有多对**——采样策略、插值方法在"精度 vs 调用次数"上的 Pareto 前沿 | E4、E5、E6 | 计算策略与优化(明示加分项) |
| 外加:容错降级实证 E7、交付要求的真实社区测试 E8 | E7、E8 | 容错降级 / 真实对比测试报告 |

### 1.2 四条实验原则

1. **台账原则**:每次 API 调用都写入 SQLite 台账(带 `experiment_id`),配额可核算、实验可复现、结果可审计。实验期用 SQLite 代替 Redis(产品期再换,行为一致)。
2. **嵌套复用原则**:50m ⊃ 100m ⊃ 200m 网格嵌套、射线共享中心前缀查询——粗分辨率方法的调用被细分辨率方法直接复用,一份数据喂多个实验。
3. **真值优先原则**:主真值用 OSMnx 本地 Dijkstra(零配额,Boeing 2017),API 密集网格仅作小范围辅真值;held-out 验证点每点只测一次。
4. **一次一变量**:每个实验一份冻结的 YAML 配置 + git commit,跑批脚本可重放。

## 4. 实验详细设计

### E0 · API 能力基线探查:「仪器规格表」

**目的**:把官方文档的"标称"变成实测的"规格"。后续所有实验的参数(超时、并发、批量大小)从这里来。

| 子实验 | 步骤 | 指标 |
| --- | --- | --- |
| E0.1 延迟画像 | 城区内随机 100 对 (o,d)(距离 200–1500m),逐个调步行算路 | P50/P95/P99 延迟;超时阈值建议 = P99×2 |
| E0.2 批量能力 | 用小规模探明批量算路接口对 walking 的支持与单请求上限(尝试 2/5/10/25 条);再取 100 对,单发 vs 批量各跑一遍,对比结果一致性 | 单请求最大对数;批量加速比;批量与单发结果一致率 |
| E0.3 限流探查 | 以 2/5/10/20 QPS 各持续 60s 打步行接口(短脉冲,勿蛮干),记录限流错误码与触发点 | 实测限流阈值;safe QPS = 观测值 × 0.8;错误码清单 |
| E0.4 POI 检索画像 | 5 个民生类目(医疗/教育/购物/药店/养老)在 2km 半径分页拉全 | 每类目原始条数/去重后条数;翻页上限;类目污染率(抽 30 条人工判) |
| E0.5 地理编码 | 10 个地址 正地理编码→逆地理编码 往返 | 往返偏差(米) |

**成功标准**:产出《仪器规格表》一张(latency / safe QPS / batch max / 日配额 / 错误码),后续 runner 全部引用它。
**预算**:≈500 次。**风险**:限流探查可能短暂触发封禁——放最后做,且每档位间留冷却。

### E1 · 坐标系一致性:最容易翻车的地方

**目的**:量化 09.4 的警告——"混用坐标 = 结果作废"——拿到答辩用的具体数字。

| 子实验 | 步骤 | 指标 |
| --- | --- | --- |
| E1.1 往返转换误差 | 20 个控制点(POI 检索返回的官方坐标),做 bd09→gcj02→wgs84→gcj02→bd09 全链往返 | 往返误差;**要求 < 1m** |
| E1.2 混用偏移量化 | 故意把 WGS84 坐标直接喂 BD09 接口,对比终点落点 | 落点偏移(预期数百米);等时圈边界点的时间偏差(分钟) |
| E1.3 全链路断言 | CoordinateService 单测 + pipeline 出口断言所有图层同 CRS | 全部通过 |

**成功标准**:`core/coord.py` 唯一转换出口,单测通过;文档记录"坐标混用使边界时间偏差达 X 分钟"。

### E2 · 测量仪器特性:噪声、对称性、单调性

**目的**:API 是仪器,先测仪器误差,才知道二分法什么时候该停、F1 差异是否显著。

| 子实验 | 设计 | 指标与用途 |
| --- | --- | --- |
| E2.1 确定性/噪声 | 20 对 (o,d) × 每对重复 10 次(间隔 >1min) | duration 的 std/IQR → **底噪 σ̂**,直接决定二分停机阈值(\|Δt\| < 2σ̂ 即收敛) |
| E2.2 对称性 | 50 对,f(o,d) vs f(d,o) | \|Δ\| 分布;若不对称,采样只按"从中心出发"方向建模 |
| E2.3 射线单调性 ⭐ | 8 条射线 × 每 100m 一点(200→1500m),检验时间随距离单调性 | 非单调区段的位置与宽度(过河/围墙/断头路)→ **二分法适用边界**:非单调区改用顺序扫描 |
| E2.4 速度合理性 | 用 E2.3 的 (distance, duration) 求 implied speed | 分布应落在 3–6 km/h;离群点即天桥/红绿灯密集区,做清洗规则 |

**成功标准**:仪器误差模型 σ(距离) 一份;《二分法适用条件清单》一份。
**预算**:≈500 次(与 E0 部分数据可复用)。

### E3 · 工程性能:Request Manager 参数标定(30% 工程分)

**目的**:批量、并发、缓存、重试各自贡献多少,用数据定默认参数,而不是拍脑袋。

| 子实验 | 设计 | 指标 |
| --- | --- | --- |
| E3.1 并发扫描 | 任务=200 对 fresh (o,d)(**每个并发档用不同 pair 集,避免缓存污染**);c ∈ {1,2,4,8,16,32} | 墙钟、吞吐(对/s)、错误率、限流次数 → 最优 c* |
| E3.2 批量 vs 单发 | 同 200 对:单发 vs 批量(E0.2 实测上限) | 请求数、墙钟、结果一致率 → 组合策略 |
| E3.3 缓存 | 同一社区测时任务连跑 3 遍 | 调用数应 {N, 0, 0};命中曲线 |
| E3.4 重试退避 | 人为把超时设为 50ms(注入 ~30% 失败),对比 固定重试 vs 指数退避 | 最终成功率、总耗时、请求风暴放大倍数 |

**成功标准**:Request Manager 默认参数表一份(并发 c*、批量 size、超时、退避基数),杀手句:"200 点测时从 X 秒降至 Y 秒,失败自愈率 100%"。

### E4 · 采样策略对比 ⭐(答辩杀手表)

**目的**:10.2 那张表,用真实数据填出来——不同采样策略在"API 调用 / 精度 / 耗时"上的 Pareto 前沿。

**实验场景**(3 个社区,覆盖 04.4 的已知陷阱):

| 社区 | 特征 | 考察点 |
| --- | --- | --- |
| A 规则路网城区 | 方格路网、无明显屏障 | 基准性能 |
| B 河流/铁路切割区 | 存在"直线 500m 实走 20min"孤岛 | **孤岛漏检、凹陷被吃掉** |
| C 老城窄巷 | 路网密、速度慢 | 插值误差上界 |

**真值**:
- 主真值:OSMnx 本地 Dijkstra 等时圈(零配额;注意 OSM 与百度数据的系统差,结论以"方法间相对比较 + B/A 社区 API 辅真值桥接"为准)
- 辅真值:A 社区 1km×1km 的 50m 密集网格(400 次)
- held-out 验证集:每社区随机 100 点(剔除距中心 <100m 的),每点实测一次 T_api,全实验冻结复用

**对比方法**(8 种,同一中心点):

| 编号 | 方法 | 预期调用量级 |
| --- | --- | ---: |
| M1 | 200m 网格 | ~100 |
| M2 | 100m 网格 | ~400 |
| M3 | 50m 网格(仅 A,1km²) | ~400 |
| M4 | 扇形 16 方向 + 二分(E2.3 停机阈值) | ~150 |
| M5 | 扇形 32 方向 + 二分 | ~300 |
| M6 | 扇形 72 方向(仅 A,饱和参照) | ~650 |
| M7 | 自适应扇形:16 起步,相邻边界半径差 > 阈值处角度加密 | ~200 |
| M8 | H3 粗网格 + 13–17min 边界带 AMR 加密 | ~250 |

> 嵌套复用:M1⊂M2⊂M3、M4⊂M5⊂M6 共享调用;全部方法共享 held-out 验证集 → 实际新增调用远小于逐方法累加。

**指标**(方法 × 社区):

- API 调用数(台账自动汇总)、墙钟时间
- held-out MAE / RMSE、**15 分钟分类准确率**(最重要单一指标)
- Precision / Recall / F1(以"圈内"为正类)
- 边界平均偏差(米,vs OSMnx 真值)、面积 IoU
- B 社区孤岛漏检率(2 个预先人工标注的孤岛点)

**成功标准**:杀手表 + Pareto 散点图(x=边界误差或 1−F1,y=API 调用数);目标句:**"边界 F1 ≥ 0.90 且调用次数 ≤ 密集网格的 20%"**。
**预算**:≈1800 次(含嵌套复用后)。

### E5 · 绕行系数标定(零新增配额)

**目的**:09.3 降级链的"经验值 1.2–1.4"换成本地实测值——漂亮的创新点(反推标定)。

**数据**:直接复用 E4 网格方法的路线数据(API 返回含 route distance)。

| 步骤 | 内容 |
| --- | --- |
| 1. 系数分布 | 每采样点:detour = route_dist / 直线距离;全域 P25/P50/P75,并按空间分块(河割区 vs 常规区) |
| 2. 兜底精度 | held-out 点用 `直线距离 × 系数 / 步行速度` 估时 vs 实测 → MAE |
| 3. 系数对比 | 固定 1.2 / 1.3 / 1.4 vs 分区标定系数,谁的兜底 MAE 最低 |

**产出**:《当地绕行系数表》 + "兜底估计 MAE = X 分钟"。

### E6 · 插值方法对比(零新增配额)

**目的**:05.2 三种插值,用同一份 E4-M2(100m 网格)样本 + 同一 held-out 验证集比出默认方案。

| 方法 | 说明 |
| --- | --- |
| IDW(p=1/2/3) | Shepard 1968;p 扫一遍 |
| 自然邻点 | Sibson 1981,`scipy.interpolate` 现成 |
| Delaunay 线性 | 流派 B 的基线 |
| (可选)Ordinary Kriging | 时间富余再做 |

**指标**:held-out MAE/RMSE、边界 F1、计算耗时、"牛眼"纹路目测评分。
**预期结论**:IDW p=2 够用 → 写进技术文档;Kriging 一句话提及。

### E7 · 降级链与 POI 清洗:容错实证

**目的**:评分明确要求"容错与降级"——用故障注入证明降级链有效,而不是只在文档里画表格。

| 子实验 | 注入方式 | 度量 |
| --- | --- | --- |
| E7.1 API 故障注入 | mock 层按 p ∈ {10%, 30%, 50%} 随机抛超时,降级为 直线×E5 系数 | 端到端任务完成度;等时圈面积误差 vs 全量真值 |
| E7.2 限流演练 | 以 2× safe QPS 持续压 60s | 令牌桶排队不报错、零 429 泄漏、恢复时间 |
| E7.3 POI 类目扩展 | 每类目:单关键词 vs taxonomy 同义词表(07.5) | 召回增量;抽 30 条人工判精度;去重规则效果(坐标<50m+名称相似>0.9) |

**成功标准**:降级矩阵表(09.3 表格的实证版):"30% 故障下面积误差仅 +X%"。

### E8 · 端到端真实社区测试(交付硬要求)

**目的**:赛题交付明确要求"真实社区对比测试报告"(10.4),本实验产出报告素材。

**步骤**:

1. 选 1 个真实社区(建议 C 类老城,问题多、效果好讲),完整跑 体检→盲区→选址 流水线
2. 记录:首跑 API 总调用数、墙钟;**立即二跑**:调用数应 ≈ 0、秒级出结果(缓存)
3. 人工抽查:随机抽 20 个系统判定的盲区格,街景/实地核对"该处 15min 内真没有某类设施?"
4. 计算:系统判定 vs 人工观察一致率

**成功标准**:首跑 ≤ 预算、二跑 ≈ 0 调用;盲区一致率 ≥ 85%;素材直接进《真实社区对比测试报告》。

## 7. 风险与注意事项

1. **限流探查(E0.3)有封禁风险**:放在 E0 最后,档位间冷却,触发限流立即停止并记录。
2. **OSMnx 真值的系统差**:OSM 与百度路网并非同一张图;结论以方法间**相对比较**为主,A 社区用 API 密集网格桥接绝对精度,报告里写明该局限(严谨性反而加分)。
3. **缓存污染实验**:E3.1 各并发档必须用不同 (o,d) 集,或显式绕过缓存;E4 各方法之间则**刻意**利用缓存做嵌套复用。
4. **评审演示日切勿跑实验**:演示环境提前预跑,靠缓存零调用(09.5 第 5 条)。
5. **AK 脱敏**:`.env` + `.gitignore`,README 只写配置方法(11.5 开源规范)。
6. **批量接口的 walking 支持性未知**:E0.2 先探明再定 E3 策略;若不支持 walking 批量,退化为"并发 + 单发"并在文档如实说明。

### E11 · 邻近点缓存(跨源复用)

**问题**:cache 以 (origin,dest) 为键,换源点全失效;但源点平移几十米,多数 dest 的
步行时长几乎不变——这部分冗余可省。
**两段式**:
1. 离线标定(零 API):利用已有异源数据(ρ 探针的 origin=边界端点、口袋/对端探针),
   对同一 dest 统计"源点相距 d 的时长差 ΔT(d)",拟合误差包络(如 P95(ΔT)≤60s 的 d*)
2. 在线 A/B(小额):新社区两条腿——A 腿正常测;B 腿先查邻近源缓存(d≤d* 直接复用,
   仅测未命中),对比总调用数与边界重建偏差
**产出**:d* 标定表 + 命中率/省钱曲线;预期省 20-40%(待验证)

### E12 · 起步向数路由(8 还是 16,免费信号预判)

**问题**:8 起步在难城(哈尔滨 k=42)会多花一轮;16 起步在易城(昆山)浪费一倍。
**信号(全部免费,先于任何百度调用)**:OSM 路网密度/各向异性、水系河网密度
(features natural=water)、POI 密度、城市规模档。
**方法**:十五城标签=弦规则收敛 k(16~87,已有),拟合可解释决策树/阈值规则
(不超过 3 个特征);留出验证(12 城训练/3 城验证轮换)。
**产出**:路由规则表(如"河网密度>X 或 aniso>Y → 16 起步,否则 8"),预期平均省 ~20%
与一次返工轮;新社区上做一次前瞻验证。
