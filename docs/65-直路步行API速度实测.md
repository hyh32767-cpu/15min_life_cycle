# 直路步行API速度实测

2026-10-16用户要求“在直线上测一下api对应的步行速度”。不使用道路直线距离除以耗时来代替沿路速度，而是以同一响应中的实际路径distance/duration计算。

## 测量

从王府井BD09中心116.417939,39.915062向北设置200/500/800/1000米坐标偏移，共4对。通过正式`/api/routes/walking`取得真实导航路径、距离、耗时和指引；通过正式`/api/travel-matrix`对照当前等时圈实际使用的矩阵耗时。

4条导航路线均为本次实时查询，调用之间等待1.1秒，避免额外提高方向接口QPS。矩阵4对中1对实时查询、3对复用本日有效真实OD缓存；没有为了制造冷启动而清缓存或重复付费。未新增整圈、设施或限流测试。

## 是否直路

前三条路线指引均为“沿王府井大街走……到达终点”。按真实路线geometry计算，路径折线长度/首尾弦长分别约1.0250、1.0033、1.0021，最大横向偏离分别4.35、8.01、9.68米。尤其500/800米两条几乎沿直路，无明显绕行。输入偏移、API路网吸附后的端点及沿路长度有细小差异，保留API实际距离，不预填200/500/800米。

1000米样本末尾右转进入柏树胡同约40米，折线/弦长约1.0422，最大横向偏离约38.59米，因此不作为严格直路证据，只保留为额外对照。

## 结论

本次直路样本中，百度步行矩阵约1.17m/s，即4.2km/h、每分钟70米，15分钟折算沿路约1050米。该值为有限样本的接口有效速度推算，不宣称为百度正式、全球固定步速参数；真实城市路网的直线覆盖半径还受绕行、接入及通行限制影响。

导航接口的距离/耗时通常约1.07～1.09m/s（短距离195米样本约0.94），但没有独立验证耗时差来自路口、接入、等待还是其他内部模型，不能直接指定原因。
