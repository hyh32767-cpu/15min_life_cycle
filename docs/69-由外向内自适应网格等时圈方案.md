# 由外向内自适应网格等时圈方案（待实现）

2026-10-16。用户要求先研究方案：参考历史扇形算法边界情况，以1.1公里、50米网格从外到内定位边界。本文仅规划，无新增百度API调用，无生产算法切换。

## 范围与目标

沿用前次明确的1.1×1.1公里方形定义：中心±550米，50米格点23×23=529个，外框88个。它是指定研究窗口，不是半径1.1公里。前次75米网格224个有效点中208个已在900秒内，说明这个窗口很可能截断15分钟可达区。新算法必须返回clipped标志和触边位置；只显示已测窗口内结果及开口，不沿窗口外框伪造900秒闭合边界。自动扩大窗口属于后续独立参数，不能悄悄把529点上限扩大。

目标：优先定位900秒边界，最终空间采样细至50米；同一时间场支持300/600/900秒三层，分析固定900秒。50米是采样尺度，既不承诺边界误差±25米，也不保证发现小于50米的障碍。

## 推荐管线

1. **统一格点及缓存。** 格点键绑定精确中心、BD09、整数50米索引、模式、有向OD；保留有效原始响应TTL。插值值不写为实测缓存。中心是逻辑锚点，若显示0秒需单列origin-anchor，不计为百度有效测值。
2. **外向内粗扫。** 初始坐标轴偏移[-550,-400,-200,0,200,400,550]，共49个位置，其中外框24个。先外后内排列，但合成约一批请求，避免24个先发再等一次节奏。所有点均属于50米基础网格；边缘粗单元宽150米，其余200米。粗扫覆盖全域，不能只扫外圈。
3. **候选单元队列。** 每个阈值分别标记四角正负、缺测、贴近阈值、鞍形、已知内部反例。优先级依次为900秒异号/缺测、900秒边界邻带、内部异常、600/300秒边界。相同优先级按最大轴偏移从大到小处理，即从外向内。
4. **200→100→50米细化。** 优先加单元边中点及内部点，坐标必须对齐50米；150米边界单元拆为50/100米，不引入75/25米点。异号单元两侧增加一格保护带。相邻观测跳变大、同一行列出现多次阈值穿越或内部探针推翻插值时，邻域同步细化，保留全部可达段。
5. **内部检查。** 同号粗单元也不能作为确定可达/不可达证明。先测可对齐的内部中心点；按风险与固定空间分层分配额外探针。近阈值、时间残差或跳变明显的单元强制细化到50米。远离阈值且检查一致的区域暂不细化，但记录estimated/interior-unverified。稀疏检查仍可能漏掉未采样口袋；要消除这种采样遗漏只能增加测点，最坏退到全529点。
6. **停止规则。** 找到首个可达点仅改变队列优先级，不终止整条行列。局部停止须满足：该轮目标边界候选已细至50米、保护带已处理、没有已发现却未解决的异常；同号内部单元只能以近似状态暂停。全局停止还需记录缺测、预算与触边情况。主圈完成可先发布，小圈继续消费同一批缓存测值；为15分钟找到边界不能阻断5/10分钟所需的内部采样。

“边界附近”初始可用|T−阈值|≤120秒作排队启发，但不是安全界或已有实测最优参数；必须在历史场上与60/180秒对照。仅凭欧氏邻近不能给时间场设全局Lipschitz常数，墙两侧可能突变。

## 绘制与判定

采用单元内分片线性插值/Marching Squares思想，分别抽取300/600/900秒。自适应单元共享的细边顶点必须一致，粗细交界补齐悬挂节点或一致剖分，不能各单元独立连线留下裂缝。50米叶子四角鞍形用确定性的双线性判别连接，同时保留拓扑不确定标志；不把虚拟中心插值当实测。发现对应风险可继续测邻点，但默认不偷偷加25米实测。

真实有限正耗时可参与线性插值；明确no_route没有有限耗时，不能随意填9999再插值，相关单元输出网格尺度的边界不确定带；网络失败等unknown掩膜。闭合环按包含关系形成Polygon洞及MultiPolygon，保留分离分量，不只取最大环。触边/缺测产生的开口保留为线，不用外框封口冒充等时线。地图、面积、圈内设施过滤、后续覆盖和报告统一消费同一版本几何及不确定标志，停止沿用“显示网格、判定射线”的双源结果。

颜色维持5分钟绿、10分钟青、15分钟蓝，同一标量场保证阈值集合嵌套。发布观测点、估计单元及线段来源，填色仅覆盖有支持的范围；过渡动画不移动实测坐标。

## 请求数量与耗时

软预算先设300个唯一位置（不是预计一定需要300），硬上限529个窗口格点，缓存命中不计新增对。预算耗尽保留未解决区域，不能宣称达到全域50米精度。5/10层增加的采样必须计入同一预算并去重。

沿用每批最多50对、满批起始间隔9秒作为实验参考。若能预先满批排队，150/250/300/529对对应3/5/6/11批，最后一批最早约18/36/45/90秒开始；加上响应才结束。这是理想满批调度估算，不是实测预测，自适应依赖、短批节奏、401/超时均会使其变慢。由外向内只改变顺序并不自动减少数量；削减量来自停止细化远离边界且检查一致的单元。

不为凑满批添加无价值点，也不每收到一个结果就发一两个请求。每轮集中收集有价值待测点，去重后组批；上一批成本决定下一批等待，所有用户共用正式限流出口。

## 先验证，再真实测速

- 使用历史实测密集场作受限查询oracle；未测位置不可用插值冒充真值。每个场限制共同覆盖区域，不拿±500米历史场外插成±550米对照。
- 测试圆形、深凹槽、内洞、复通、多分量、窄桥、跳变、鞍形、边界触框、未知、预算耗尽。合成场测试算法行为，与真实历史成绩分开。
- 比较“外向内逐行首命中停止”“本方案”“全50米网格”。保留未参与采样的评估点，报告FP/FN、面积IoU、边界距离分位、洞/复通命中、未知面积和唯一查询数；未发现不等于保证不存在。
- 先用历史王府井、东花市、上海、义乌、哈尔滨、遵义等现有覆盖数据复查难例，不依据评估集反向挑探针。达成数量/精度可接受的折中后，再单地点真实对照；本轮不发真实请求。

## 网络经验及适用边界

- [Valhalla架构](https://valhalla.github.io/valhalla/contributing/architecture/thor/isochrones/)：道路图按最小代价向外扩展，把时间写入二维网格再抽等值线。可借鉴“时间场→轮廓”，但其停止成立依赖完整图的Dijkstra次序；百度单中心黑盒OD不能直接照搬为空间外向内首命中停止。
- [ContourPy算法说明](https://contourpy.readthedocs.io/en/stable/description.html)：网格边阈值穿越、鞍形连接、掩膜、开口/闭环和洞关系处理。
- [D3 contour](https://d3js.org/d3-contour/contour)：规则栅格生成MultiPolygon，平滑是边上线性插值。D3默认取大于等于阈值，本项目可达是小于等于时间阈值，不能直接照搬方向；也不能将未测格填零交给绘图库。

这些资料支持网格绘制和拓扑处理，没有证明本项目的稀疏外向内停止规则可无遗漏。推荐方案是基于历史反例提出的工程折中，尚未实现或测出精度/节省比例。
